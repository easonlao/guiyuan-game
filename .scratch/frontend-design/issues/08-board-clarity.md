# 棋盘状态、阴阳与回合可读性

Status: resolved

## 用户需求

用户无法通过棋盘理解状态，动画需要花时间解读，阴阳不直观、行动方和当前天干归属不明确。用户指定使用阴阳鱼，等级 -1 崩坏、0 无色虚空、1 五行色、2 发光。按此实现而不改规则。

## 实现契约

- 保持玩家内外环、节点位置及交互契约。每个五行节点同时拥有阴阳两种状态，两条鱼必须各自呈现对应的等级；阴阳不能误画成两个玩家或两条环。真实S形太极鱼，左阴右阳，减少装饰圈线。元素标题/标签不能挡鱼形。
- -1 灰暗破碎、裂痕或缺口；0 无元素色的安静虚空；1 足够饱和的对应五行色；2 同一五行色发光。发光不可将所有五行变成同一金色。无需重复数值、层层描边、轨道刻度与连接线来编码状态。保留一行简短图例，颜色之外也通过形态辨识等级。
- 玩家环明确“你 / 天道”或角色名，避免只有“己 / 敌”的微小标签。行动方明确突出显示，当前天干紧邻归属与动作阶段。顶栏、玩家卡、中央天干所有显示一致。
- 动画按“谁使用什么 → 作用到哪里 → 哪些阴/阳状态发生什么变化 → 回合交接”组织。仅必要的单条飞行或目标脉冲，不同时堆叠光环、拖尾、震屏和装饰飞行。状态前后变化必须准确且可读；对PASS/无节点变化不能伪造落点。变化说明至少有短暂停留，不能被下一回合立刻覆盖。
- 保持动画期间投影在落点更新、交接后再换天干/行动方，避免旧行动和新天干混用。沿用cancel/restart/dispose守卫。
- 顺带解决05已知微信胶囊占据顶部空间的问题：可用menu rect bottom时让顶栏避让，适配320×568等小屏。允许 board optional content bounds，浏览器默认几何契约不随意更改；Rune中心必须与board一致。不要让抬高header后压到棋盘或操作区。
- 保留已经用户接受的人物素材及缓存优先加载。核心规则/AI不修改。

## 验收

在浏览器320×568、390×844、460×900预览，构造-1/0/1/2不同阴阳状态并截图；真实动作验证文字归属/变化与时序，并录一个短演示。必要行为测试验证阴阳独立编码、真实等级变化与动画交接、微信safe header布局。运行check:quick、build:minigame、verify，交付game.js逐字节匹配；Reviewer审查。原生微信真实截图由用户本地确认，不声称已经跑过微信模拟器。


## 实施结果

- 每个节点改为阴阳两条 S 形鱼，各自投影 -1/0/1/2；元素标题位于鱼形外，二级状态使用对应五行的明亮径向渐变、光边与闪点。删除轨道刻度、归一外圈和盘面候选连线，保留内外环几何与路径查询契约。
- 明确“你 / 天道”环与当前天干归属。行动期间保留旧行动方与轮数，落点才更新棋盘和比分；新增 result 停留，再交接。上一招可展开所有真实阴阳变化并跨回合保留；目标未变与 PASS 不伪造落点冲击。
- 飞行减为单条路线与目标单次脉冲，去掉震屏、复合光环、拖尾和遮挡顶部标题的重复动作气泡。天命揭牌明确 P2 归属并在落点显示真实变化。
- 原生胶囊 bottom + 8 决定顶部边界；小屏重新排版按钮后计算棋盘可用范围，符文中心与棋盘同步；接口缺失/异常/不合理数值回退。未修改核心规则、AI、人物 PNG 和缓存优先加载。
- LLD §4.1 已更新阴阳状态、落点/交接、上招记录及可选内容边界契约。
