## 范围

- 失败时自动检查微信代码包中的实际 PNG，记录路径、字节数、签名及具体文件系统错误，不打印图片内容。
- 读取成功后通过小游戏自有用户目录写入缓存文件，再用微信原生图片对象加载绝对路径；最多一次备用尝试。
- 成功解码前不注入图集，失败保持可运行且明确记录原因；正常成功路径不增加文件系统工作。
- 仅移除交付 PNG 的 caBX 附加元数据，IHDR/IDAT/IEND 不变，像素校验必须一致；原始生成图片保留。此兼容性处理不代表已证实元数据导致本次失败。
- 用入库 game.js 的真实入口验证恢复、读取/写入错误、二次解码失败与 API 不可用等边界，重建并通过 verify 后推送。

## 实施结果

- 微信加载逻辑集中在 `character-atlas-loader.ts`。原路径触发 onerror 后自动 readFile 读取实际包内路径，验证 PNG 签名，日志仅记录文件路径、字节数与 8 字节 magic，不输出图片内容。
- 文件读成功后原样 writeFile 写入 `wx.env.USER_DATA_PATH/guiyuan-characters.png`，再创建新 wx 图片对象加载缓存绝对路径；用硬门槛确保最多一次备用解码，重复或过期回调不会再次启动。
- 图片对象通过模块 pendingImages 集合强引用保留，onload / onerror 后解绑并释放；成功解码前始终使用备用人物。正常首尝加载不读写文件系统。
- 自动报告文件读取、无效 PNG、缓存写入、二次解码以及缺失 FS / USER_DATA_PATH 等具体失败阶段；原生错误只抽取有限的 errMsg / message / type 与 error / detail / cause 字段。
- 交付 PNG 仅移除 caBX 附加块，由 1637564 字节变为 1613898 字节；IHDR、IDAT、IEND 保持字节一致，1254×1254 解码 RGBA 像素 SHA-256 前后一致：`43e6990cbb05dce7e4f151202cab9ec09d79bf9a9ca17249490311718411b40d`。原始生成图片未修改。该处理不证明 caBX 是用户本次失败的原因。
