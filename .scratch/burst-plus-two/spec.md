# Spec: 恢复爆发动作的双级作用与满溢则亏 (burst-plus-two)

## Problem Statement

玩家看到的与棋盘上发生的对不上。

按钮文案写着「消耗木·生火**+2**」「消耗木·克土**-2**」（`src/minigame/action-button-formatter.ts:87,97`），但实际只作用 **1 级**：一次强化只把相生节点抬一级，一次强破只把相克节点压一级（`src/core/logic/ActionResolver.ts:243,283`）。

这不是显示 bug，是**重构丢失了原设计**。重构前的 JS 实现里，强化是「消耗自身 1 点、**强化生属性 2 次**」，每次按阴优先重新选侧（`ca2bdde:legacy/src/logic/actions/ActionResolver.js:52-93` 的 `applyBurst`，强破同构见 `:99-131`）；归档的规则基线报告记录的结果状态也是双级作用——`BURST` 后「target yin becomes 2」、`BURST_ATK` 后目标成为 `(-1,-1)`（`docs/archive/headless-rule-baseline.md:17-18`）。重构为纯 TS 时退化成了单级，GDD §2.3 也一并被改写成「使其对应侧 +1」。

于是同一个事实有了四个家、三个版本：旧实现 `+2`、UI 文案 `+2`、GDD 与现行代码 `+1`。

叠加第二个问题：**亢极设定引入之后，「溢出的那一级直接丢失」不再符合直觉**。原设计里相生节点满盘时第二次强化是空操作；但现在 GDD 已有「天道满溢则亏」的亢极散气——满盘再受滋养却毫无代价，与亢极的直观相反。玩家把相生节点养到 `(2,2)` 后再强化，会看到一个和亢极散气互相矛盾的结果。

## Solution

把爆发动作恢复为**双级作用**，并让满盘时的溢出**与亢极一致地「满溢则亏」**。

- **强化 (`BURST`)**：消耗源节点阴侧 1 级，对己方相生节点连做两次 `+1`。每次 `+1` 之前重新读盘面、按阴优先选侧（阴侧未满则加阴，阴侧已满则加阳）。若某次 `+1` 面对的是亢极 `(2,2)`，该次改为对**阴侧** `-1`（阴优先），计 0 分。
- **强破 (`BURST_ATK`)**：消耗源节点阳侧 1 级，对对手相克节点连做两次 `-1`，每次按阴优先选侧，到道损 `-1` 即止。底部没有对应亢极的机制，因此**不反转、不溢出**。
- **门槛放开**：相生节点已是 `(2,2)` 时仍可发动强化，相克节点已是 `(-1,-1)` 时仍可发动强破——两者盘面净零，但都仍然换取一次连动与动作分。
- **化 (`TRANS`) 与吸纳 (`AUTO`) 不变**：它们在 `(2,2)` 上仍不可发动（不给连动，放开只会产生空转按钮）。

结果：按钮文案的 `+2/-2` 成为事实，GDD、代码、UI 三者重新一致。

## User Stories

1. 作为玩家，我希望强化把相生节点抬高 **2 级**，这样按钮上的 `+2` 才和实际效果一致。
2. 作为玩家，我希望强破把相克节点压低 **2 级**，这样按钮上的 `-2` 才和实际效果一致。
3. 作为玩家，我希望两次作用**逐次重新判定作用侧**，这样 `(1,0)` 的相生节点收到强化后变成 `(2,1)` 而不是 `(2,0)`。
4. 作为玩家，我希望 `(0,0)` 的相生节点收到强化后变成 `(2,0)`（两级都落在阴侧），这样「阴优先」是可预期的。
5. 作为玩家，我希望 `(1,1)` 的相生节点收到强化后变成 `(2,2)`，一次强化把节点推到亢极。
6. 作为玩家，我希望 `(2,1)` 的相生节点收到强化后变成 `(1,2)`——第一级补阳到 `(2,2)`，第二级因满溢而扣阴。
7. 作为玩家，我希望 `(1,2)` 的相生节点收到强化后仍停在 `(1,2)`，同样走满溢则亏。
8. 作为玩家，我希望 `(2,2)` 的相生节点收到强化后仍停在 `(2,2)`，净零但**仍然换到一次连动**。
9. 作为玩家，我希望满溢则亏扣的是**阴侧**（阴优先），而不是按抽到的天干极性扣——强化的选侧逻辑不该因为它而变成与天干极性相关。
10. 作为玩家，我希望满溢则亏那**一级计 0 分**，与亢极散气一致，不要出现「强化自己的节点反而赚状态分」。
11. 作为玩家，我希望强破对 `(2,1)` 的相克节点作用后得到 `(0,1)`（两级都扣在阴侧）。
12. 作为玩家，我希望强破对 `(0,0)` 的相克节点作用后得到 `(-1,-1)`（阴侧扣到底后转扣阳侧）。
13. 作为玩家，我希望强破对 `(-1,-1)` 的相克节点作用后仍停在 `(-1,-1)`，净零但**仍然换到一次连动**。
14. 作为玩家，我希望强破在道损 `-1` 见底即止，不要像强化那样反转回涨。
15. 作为玩家，我希望爆发**照旧消耗源节点 1 级**（强化耗阴、强破耗阳），双级作用不改变这个代价。
16. 作为玩家，我希望化与吸纳在 `(2,2)` 上仍然不可发动，不要多出两个空转按钮。
17. 作为玩家，我希望爆发**照旧受「单次大回合禁止二次爆发」约束**，连动回合里不出现第二次爆发。
18. 作为玩家，我希望无头推演（AI 对局）与人类对局使用**同一套**爆发规则，这样平衡测试的结论对真人对局也成立。
19. 作为设计者，我希望 GDD §2.3 用一张**完整的真值表**承载这条规则，而不是一句「对应侧 +1」。
20. 作为设计者，我希望 §2.4「单向极端封死」的枚举随门槛放开而修订——相生目标双加持时强化仍然可选。
21. 作为设计者，我希望这条决策以 ADR 记录（为什么是 2 级、为什么满溢则亏、被否决的方案是什么），规则正文仍留在 GDD。
22. 作为维护者，我希望动作载荷里**不再携带爆发动作的目标侧**，因为目标侧在解析时逐步决定，预先钉死的那个值已经无意义。
23. 作为维护者，我希望 `minigame/game.js` 构建产物重新生成，并且 `check:artifact` 逐字节对账通过。
24. 作为维护者，我希望这次规则改动之后重跑无头平衡基准，确认三条护栏（归元率、先手胜率、堆内存）仍然全绿。
25. 作为维护者，我希望 AI 估值器与双级作用**对账**过，确认它不会因为一次跳跃两级而静默改变 AI 的取舍口径。

## Implementation Decisions

**记法**：节点状态写作 `(阴, 阳)`，与表现层「左阴右阳」一致。等级取值域为 `-1 | 0 | 1 | 2`，没有 `-2`。

**核心规则：强化真值表（全部 16 种目标状态，已用真实计分器验算）**

| 目标 | 结果 | 状态分 | 归一里程碑 | 合计 |
|---|---|---|---|---|
| `(-1,-1)` | `(1,-1)` | 300 | 0 | 400 |
| `(-1,0)` | `(1,0)` | 300 | 0 | 400 |
| `(-1,1)` | `(1,1)` | 300 | +60 | 460 |
| `(-1,2)` | `(1,2)` | 300 | +60 | 460 |
| `(0,-1)` | `(2,-1)` | 300 | 0 | 400 |
| `(0,0)` | `(2,0)` | 300 | 0 | 400 |
| `(0,1)` | `(2,1)` | 300 | +60 | 460 |
| `(0,2)` | `(2,2)` | 300 | +60 | 460 |
| `(1,-1)` | `(2,0)` | 400 | 0 | 500 |
| `(1,0)` | `(2,1)` | 300 | +60 | 460 |
| `(1,1)` | `(2,2)` | 400 | 0 | 500 |
| `(1,2)` | `(1,2)` | 200 | 0 | 300 |
| `(2,-1)` | `(2,1)` | 300 | +60 | 460 |
| `(2,0)` | `(2,2)` | 300 | +60 | 460 |
| `(2,1)` | `(1,2)` | 200 | 0 | 300 |
| `(2,2)` | `(2,2)` | 200 | 0 | 300 |

**核心规则：强破真值表（动作分 80；状态分随「对手归一节点数」缩放，此处取归一数 = 2、系数 0.66 作为基准）**

| 目标 | 结果 | 状态分 | 合计 |
|---|---|---|---|
| `(-1,-1)` | `(-1,-1)` | 0 | 80 |
| `(-1,0)` | `(-1,-1)` | 198 | 278 |
| `(-1,1)` | `(-1,-1)` | 330 | 410 |
| `(-1,2)` | `(-1,0)` | 264 | 344 |
| `(0,-1)` | `(-1,-1)` | 165 | 245 |
| `(0,0)` | `(-1,-1)` | 363 | 443 |
| `(0,1)` | `(-1,0)` | 297 | 377 |
| `(0,2)` | `(-1,1)` | 297 | 377 |
| `(1,-1)` | `(-1,-1)` | 264 | 344 |
| `(1,0)` | `(-1,0)` | 264 | 344 |
| `(1,1)` | `(-1,1)` | 264 | 344 |
| `(1,2)` | `(-1,2)` | 264 | 344 |
| `(2,-1)` | `(0,-1)` | 231 | 311 |
| `(2,0)` | `(0,0)` | 231 | 311 |
| `(2,1)` | `(0,1)` | 231 | 311 |
| `(2,2)` | `(0,2)` | 231 | 311 |

**逐次施加，而不是一次性平移。** 两级作用必须实现为两次独立的 `±1`，每次之前重新读盘面。这是真值表里 `(1,0)→(2,1)`、`(2,1)→(1,2)` 两格唯一可能的成因；实现成「同一侧 ±2」或「阴阳各 ±1」都会给出不同的表。

**满溢则亏的作用侧是阴优先，不是天干极性。** 亢极散气按抽中天干的极性扣级，是因为它本身就是天干触发的强制动作；强化不是。若让溢出那一级跟着天干极性走，强化就会在角落情形里变成「与天干极性有关」，而 GDD §2.3 明写门槛与天干极性无关。

**满溢则亏那级的计分无需特判。** 现行计分函数对**非攻击的 `2→1` 转移**本来就没有分支、返回 0；与亢极散气的 0 分天然一致。要不要给它记分，是平衡阶段的调参项，不进本次实现。

**源节点消耗维持现状**：强化扣阴侧 1 级、强破扣阳侧 1 级，都不计状态分。源节点因此失去归一时**不扣分**（归一里程碑只计正增量）。

**候选生成门槛放开。** 强化的生成条件从「源节点已归一**且**相生节点未达 `(2,2)`」放宽为「源节点已归一」；强破同理，从「**且**相克节点未达 `(-1,-1)`」放宽为「源节点已归一」。二者仍受「连动额外行动中禁止二次爆发」约束。

**契约变更：爆发候选不再携带目标侧。** 既然作用侧在解析时逐次决定，候选载荷里预先钉死的那个目标侧字段对爆发动作失去意义——强化的候选只保留源节点与「消耗阴侧」，强破只保留源节点与「消耗阳侧」。该字段对吸纳、调息、化、破仍然保留，不要整体删除。

**化与吸纳的门槛不变**：相生节点 `(2,2)` 时仍不生成化，虚空/道损时仍只有吸纳。

**表现层不需要改文案**：按钮文案本来就是 `+2/-2`，本次改动让它成为事实。`minigame/game.js` 是入库产物，需要重新构建。

**AI 估值器要对账，但不重调口径。** 现行估值器用「动作前后盘面差分」计价：形状类项（致道损、破归一、点亮虚空、达成亢极）**逐侧判定**，对双级跳跃每侧各记一次，不会系统性少记；差分类项（普通降级压制）随级数缩放，两级就是两倍。唯一需要记下的是：净零爆发（目标 `(2,2)` / `(-1,-1)`）在差分模型下目标侧**看不到任何变化**，而计分器因两次转移给出分数——这是估值口径与计分口径的既有差异，属于平衡阶段，不在本次实现内。

## Testing Decisions

**好测试的标准**：只断言外部可观测行为——给定盘面与动作载荷，断言结算后的**盘面状态、分数增量、连动标志、候选集合**；不断言内部函数调用、分支命中或中间变量。盘面不可变性（未改动的节点保持引用相等）沿用现有断言风格。

**接缝（3 个，全部已存在，不新开）**

1. **`ActionResolver.resolve(state, payload)`** —— 纯函数 `state + payload → { nextState, scoreDelta, extraTurn }`。承载真值表、满溢则亏、强破封底、计分与连动。先例：`tests/core/action-resolver.test.ts`。
2. **`getAvailableActions(state, tianGan, options?)`** —— 候选生成。承载门槛放开（目标 `(2,2)` 仍生成强化、`(-1,-1)` 仍生成强破）与爆发候选的新形状。先例：`tests/core/action-candidates.test.ts`。
3. **`benchmark:headless` + `GuardrailBand`** —— 平衡后果，不属于规则正确性。先例：`tests/core/ai-evaluator-benchmark-guardrails.test.ts`。

**为什么不压成一个接缝**：能同时盖住 1 与 2 的最高点是 `TurnManager`，但仓库约定规则细节在纯核心里测，`TurnManager` 只测调度、连动与回合交接；把规则断言搬过去会让测试变慢并耦合状态机。

**要写的测试**

- 强化与强破的**全 16 状态表驱动测试**（`-1|0|1|2` 的阴阳组合），逐格断言结果状态；这是本次规则的最强覆盖。
- 满溢则亏：`(2,2)`、`(1,2)`、`(2,1)` 三格的结果与「溢出那级计 0 分」。
- 强破底部：`(-1,-1)`、`(0,-1)`、`(-1,0)` 三格，断言不反转。
- 门槛放开：目标 `(2,2)` 时强化仍在候选集内；目标 `(-1,-1)` 时强破仍在候选集内；连动回合中两者都不在候选集内。
- 化与吸纳的门槛**不变**：目标 `(2,2)` 时化仍不在候选集内。
- 契约：爆发候选不再带目标侧字段；吸纳/调息/化/破的候选形状不变。
- 计分：源节点消耗不产生状态分；真值表里的状态分与里程碑分与上表一致。
- 表现层：按钮文案保持 `+2/-2`（防回归）。

**要改的既有测试**：断言旧单级行为的用例（`tests/core/action-resolver.test.ts` 的 BURST/BURST_ATK 用例、`tests/core/scoring-behavior-construction.test.ts`、`tests/core/scoring-attack-buff.test.ts`、`tests/core/attack-progress-scale.test.ts`、`tests/core/headless-config-injection.test.ts`、`tests/core/convert-gate-boundary-matrix.test.ts`、`tests/core/action-candidates.test.ts`、`tests/core/dead-knob-census.test.ts`、`tests/core/action-value-census.test.ts` 等），逐个按新真值表校正。

**平衡**：规则与测试全绿后跑 `benchmark:headless`，对照 `GuardrailBand` 的三条带（归元率 0.89–0.95、先手胜率 0.47–0.51、堆增量 ≤ 15MB）。不达标的处理属于平衡阶段，不在本 spec 内。

## Out of Scope

- **ADR 0016 正文**：决策记录单独出票（为什么是 2 级、为什么满溢则亏、被否决的方案）。
- **GDD §2.4 与 LLD 的正文回写**：单独出票。规则正文归 GDD，契约归 LLD。**例外：GDD §2.3 的规则行（真值表与两句门槛）随实现票一起落**，不留「GDD 说 +1、代码做 +2」的窗口。
- **平衡调参**：`POINTS_CONFIG` 的任何数值改动、满溢则亏那级要不要计分、AI 估值权重重调。
- **AI 估值器的估值口径重做**：只要求本次改动不让它静默错位；把它改成按两级计分是另一件事。
- **表现层的其他变化**：动画、特效、播报文案、连动提示。
- **微信开发者工具中的人工验证**：`minigame/game.js` 的构建与逐字节对账属于本 spec，真机交互验证不属于。
- **五行归元与终局规则的任何改动**。

## Further Notes

**证据链（这是证据，不是定义）**：五条独立痕迹都指向 2 级——重构前的 JS 实现（`applyBurst`/`applyBurstAtk` 显式连做两次并带调试日志）、现 UI 按钮文案、归档的规则基线报告记录的结果状态（`BURST` 后目标阴侧到 2、`BURST_ATK` 后目标成为 `(-1,-1)`）、旧计分模型把一次爆发记成「三次成功的子步骤」、以及项目负责人的记忆。现行 GDD 与代码的 `+1` 是重构产物。

**与亢极散气的关系**：两者都实现「满溢则亏」，但触发与选侧不同——亢极散气是抽中天干节点为 `(2,2)` 时的强制动作、按天干极性扣级、计 0 分；强化里的满溢则亏是动作中途溢出、按阴优先扣级、同样计 0 分。它们不该合并成一个机制，但结果应当一致。

**已知风险（留待平衡阶段观察）**：门槛放开后，爆发在源节点已归一时**总是可选**。在亢极附近，强化会退化成「最低档分 + 一次连动」的纯节奏/刷分动作——真值表里 `(2,1)`、`(1,2)`、`(2,2)` 三格合计都是 300，是强化全场最低档；强破在 `(-1,-1)` 只有 80 分，是强破全场最低且只有动作分。另有一个真实代价：源节点是 `(1,1)`/`(1,2)`（强化）或 `(1,1)`/`(2,1)`（强破）时，消耗会**让源节点失去归一**（不扣分，但拖慢五行归元）。这些数字应在平衡基准里被观察到，而不是被假设。

**受影响的既有结论**：ADR 0002 曾因「爆发刷分垄断」砍掉爆发的稀有度加成。双级作用会重新抬高爆发的收益，因此平衡阶段必须重跑护栏，而不是沿用旧结论。
