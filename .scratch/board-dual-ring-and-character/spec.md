# Spec: 法盘同心双环与角色放大

status: ready-for-agent

> 本 spec 是 `/to-spec` 从一轮 grilling 对话合成的产物。几何与接口决策已落 `docs/adr/0015-board-dual-ring-inner-outer.md` 与 `docs/LLD.md` §4.1，术语已落 `GLOSSARY.md`（己方盘 / 对方盘）。本 spec 不复述这些文档的正文，只固定范围、用户故事与测试口径。

## Problem Statement

玩家盯着微信小游戏的屏幕，遇到三个问题：

1. **分不清棋盘是谁的。** 规则层每个玩家各有一块五行盘（己方盘 / 对方盘），但屏幕上只有一块法盘。这块盘在半回合切换时**静默改换身份**——显示的是「当前行动方」的盘，却没有任何标识。更糟的是，「破 / 强破」要打的是**对方盘**的相克节点，而对方盘完全不可见，玩家做攻击决策时拿不到必需的信息。
2. **法盘上有重复的几何。** 大圈（5 个五行主印，左右半环表阴阳等级）外面又有一圈小圈（10 个阴阳槽位圆），两圈表达的是同一批数据——外圈唯一独有的信息只是「阴」「阳」两个字。重复的几何把盘撑到占屏宽 79%，挤掉了角色和对方盘本该占的空间。另外，内环还有 5 条「相克星弦」连线，而己方盘内部没有任何动作走相克——这 5 条线没有动作对应，是纯装饰。
3. **角色没有存在感。** 屏幕上的人物是全身像素画，有 4 种姿势（待机/攻击/结印/受击）、呼吸浮动、气泡与横幅，但整个角色只有约 46px 高，装在 54×54 的框里贴在屏幕边缘，所有表现力在小尺寸下都感知不到。

## Solution

1. **法盘改同心双环。** 一块盘，内外两环：内环恒为己方盘（当前钉死 P1，人类），外环恒为对方盘（当前钉死 P2，AI）。外环相对内环**逆时针偏移 2 格（144°）**，使每根射线上「己方克对方」，且内外永远不是同一五行。由此「破 / 强破」固定为**沿当前射线向外一格**，「化 / 强化」固定为**沿内环顺时针一格**。删除内环内部的 5 条相克星弦（无动作对应）与外圈 10 个槽位小圆（与主印半环重复）。双方盘不再按行动方切换身份。
2. **角色放大。** 把现有的全身像素角色从约 46px 放大到约 100–120px，提高逻辑分辨率重画（不 `ctx.scale`），保留并强化现有姿势/呼吸/气泡/横幅，新增「归一庆祝」与「终局胜负」两类反馈。

## User Stories

1. 作为玩家，我想随时同时看到己方盘和对方盘，这样我才能评估「破」能打中对方哪个节点。
2. 作为玩家，我想不用记「现在这块盘是谁的」，这样我不会在换半回合时看错盘面。
3. 作为玩家，我想抽中一枚天干后立刻看出它能打到对方哪个元素，这样我能更快做决策。
4. 作为玩家，我想攻击的方向在盘面上是固定可预测的（向外=打对方），这样我能形成稳定的视觉直觉。
5. 作为玩家，我想「化」的方向在盘面上是固定可预测的（顺时针=养自己），这样我能预判能量流向。
6. 作为玩家，我不想看到没有玩法含义的连线，这样我不会误以为己方元素之间能互相攻击。
7. 作为玩家，我想不重复地看到每个节点的阴阳状态，这样盘面更干净、更省空间。
8. 作为玩家，我想分清「这是己方的归一」还是「这是对方的归一」，这样我能判断谁更接近五行归元。
9. 作为玩家，我想清楚地辨认每个节点的阴侧和阳侧及其等级，这样我能决定要不要「调息」。
10. 作为玩家，我想角色在有动作时有明显反应（施法/受击/归一/胜负），这样对局更有反馈感。
11. 作为玩家，我想角色足够大、能看清姿势变化，这样表现力不会被尺寸吞掉。
12. 作为玩家，我想在我达成归一或赢下对局时角色有庆祝，这样里程碑有仪式感。
13. 作为玩家（小屏设备），我想法盘和角色都读得清，这样我不需要放大屏幕。
14. 作为色觉障碍玩家，我想不靠颜色也能读出阴阳等级，这样我不会看不清状态。

## Implementation Decisions

**几何与归属（决策已固化，见 ADR 0015 / LLD §4.1，此处只列影响面，不复述正文）**

- `BoardView` 由单盘投影改为**同心双环**：内环 = 己方盘（钉死 P1），外环 = 对方盘（钉死 P2），外环逆时针偏移 2 格。
- 删除内环 5 条相克星弦；保留内环 5 条相生边（表「化」），新增 5 条跨环径向线（表「破」）。
- 删除外圈 10 个阴阳槽位小圆；阴阳状态改由主印左右半环承载（左 = 阴、右 = 阳），等级用**形状档位 + 面积 + 颜色**三重冗余表达（虚空 = 极细暗弧、道损 = 断口弧、点亮 = 实心、加持 = 双线 + 圆点计数），不只靠颜色。
- 内外环区分用**环级**表达（内环暖色底晕 + 「己」徽记，外环冷色底晕 + 「敌」徽记），主印本体保持五行本色——不再用「己暖 / 敌冷」给主印换色，避免与五行本色冲突。
- 归一 / 亢极高亮按半径（内 / 外环）天然分层，并叠加归元进度读数（「己 3/5 · 敌 1/5 归一」）。
- 连线高亮语义改为「当前动作会走哪条线」，不再是「源主印点不点亮」。

**接口契约（LLD §4.1）**

- `BoardView.update` 由吃单盘改为同时吃己方盘与对方盘两块快照。
- `BoardView.getSlot` 由 `(element, polarity)` 改为 `(player, element, polarity)`。
- `RuneFlightView` 飞行落点唯一来源是 `getSlot(player, …)`，调用方传入被作用方的 `player`（攻击类为对方，其余为己方）。
- `GameScene` 删除所有「按行动方切盘」的逻辑，改为一次投影两块盘。

**角色**

- 现有全身像素角色重画放大到约 100–120px，提高逻辑分辨率（非 `ctx.scale` 放大）。
- `CharacterActionState` 联合类型扩展，新增「归一庆祝」「终局胜 / 负」状态，绘制与配色映射同步更新。
- 「归一庆祝」用现成的 `node:stateChanged` 事件驱动（某侧由 <1 变 ≥1 且对侧已 ≥1 时触发），不在场景里手写盘面比对。
- 角色布局回顶部左右角（放弃放盘侧——空间算不出来）。

**布局与可读性**

- 屏幕自上而下：顶部（回合条 + 双方角色 + 比分）→ 中部法盘 → 底部动作按钮栏（仅多候选时显示）。
- 法盘可读性下限：主印半径 ≥ ~22px（五行名字号 ≥ 11–12px）；375px 宽屏上双环可行，更小屏需另行降级（见 Out of Scope）。

## Testing Decisions

**什么是好测试**：只测外部行为与公开契约，不测实现细节。坐标与几何属于本 feature 的**契约**（盘布局是契约不是样式），因此坐标断言是被允许且被要求的；但绘制调用次数、内部缓存、私有字段不属于契约，不应断言。期望值一律来自**独立推导**（按环半径与角度手算坐标），不从被测代码抄。

**测试哪些模块**：

- `BoardView`（双环几何）：内环 = 己方、外环 = 对方、外环偏移 2 格后每根射线「内克外」的方位断言；双盘 `update` 后各主印阴阳等级投影；归一 / 亢极按半径分层；删除相克星弦后只剩相生边 + 径向线。
- `BoardView.getSlot(player, …)`：传入己方 / 对方返回正确环上的槽位坐标；未知玩家 / 元素抛错。
- `RuneFlightView`：`flyTo(player, …)` 的目标落点 = 对应环上的槽位坐标；起点不依赖法盘。
- `GameScene`：不再切盘——同一时刻两块盘都在投影；攻击动作飞向对方环、养己动作飞向己方环；`update(p1, p2)` 后飞行期不再换盘。
- `CharacterView`：新状态（归一 / 胜负）的姿势与配色映射；`node:stateChanged` 触发归一庆祝。
- 既有测试：`tests/core/minigame-board-view.test.ts` 的坐标 / 弦数 / `getSlot` 硬编码断言会因本 feature 失效，**整片重写**；`minigame-game-scene.test.ts` / `minigame-rune-flight-view.test.ts` 中 `getSlot` 调用点同步改签名。

**Prior art**：`tests/core/minigame-board-view.test.ts`（手算坐标 + 投影断言）、`tests/core/minigame-rune-flight-view.test.ts`（生命周期 + 落点断言）、`tests/core/minigame-game-scene.test.ts`（端到端推进 + 同种子确定性）——沿用同一套「真实 canvas + 伪 wx + 手算期望」的做法。

## Out of Scope

- **小屏降级方案**（< 375px 宽屏，如外环退化为紧凑节点）：本 spec 只保证 375px 主流宽屏；更小屏的降级单独评估。
- **角色超过 ~120px 的全身 Q 版**与**引入真实美术资源 / 音效 / 帧动画**：另一条工作线（GDD §4 外观系统、FSR 远程分包），本轮不做。
- **本地双人（Local PVP）下内环轮换**：GDD §3 仍是「规划中」，当前钉死内 = P1，不为它付代价。
- **改核心层规则**：本 feature 只动表现层，`src/core/` 一律不碰。
- **微信真机验证**：仅做浏览器等价验证（伪 wx + 真 canvas）；真机 Profiling 仍按 `docs/HLD.md` §4.6 单独进行。
