# 05: 重做 check:delivery 断言③——用树判据，不用计数棘轮

**Type:** task
**Blocked by:** None
**Status:** ready-for-agent

**What to build:** 把 `scripts/check-delivery.mjs` 的断言③（「无新增孤儿提交」）从**计数棘轮**改成**树判据**。改完删掉基线常量。

## 为什么必须改（实测证据）

计数棘轮**按构造每轮必红**。squash + rebase 的流程每轮都抛弃原始提交；分支一删，它们就变成不可达。所以每交付一轮，计数必然上涨：

| 时点 | 不可达提交数 | 事件 |
|---|---|---|
| 2026-10-25 基线 | 479 | 线性化重写后的实测值 |
| S1 交付 + 收尾 | **482**（+3） | 弃掉 `1066fb2`、`02bd21c`、`3979c3b`（S1 的 spec / ticket / 快照提交） |
| S2 交付 + 收尾 | **484**（+5） | 同上，多三条本轮的 spec / ticket / delivery 提交 |

判红的那些提交全是**交付残渣**，内容早已在 main 里。一个每次都红的门禁比没有门禁更糟：没人会再跑它。按脚本自带的建议「确实作废才重钉基线」，等于每轮手工重钉一次——那这条断言就没在拦住任何东西。

## 改法：问「有没有 main 里没有的孤儿工作」

真问题不是「不可达提交有几个」，是「**有没有内容不在 main 里的不可达提交**」。但只靠树判据**太宽**——二分二版实测踩过（见下）。最终口径是两个条件与：

```
不可达提交中，author date 晚于水位线（WATERMARK = 2026-10-20）
且 树不在 main 的树集合里  →  报红
```

1. `git fsck --unreachable --no-reflogs` 取不可达提交。
2. `git log --format=%T <base> | sort -u` 取 main 的树集合（`<base>` 默认 `origin/main`，与断言① 同源）。
3. 逐条过两道滤：日期早于水位线的放过；树在集合里的放过。
4. 剩下的报红并列出提交本身。

两个条件各管一头：**树判据**滤掉 squash/rebase 的交付残渣（它们的树就是 main 里那些交付提交的树）；**水位线**滤掉线性化之前的 30 个历史中间态。这样没有跑步机——不像计数棘轮那样每轮要手工重钉。

### 第一版判据（只有树判据）实测不成立：34 个命中，33 个是假阳性

| author 日期 | 个数 | 性质 |
|---|---|---|
| 2026-10-05 | 1 | 线性化前的历史 |
| 2026-10-09 | 14 | 同上（含 `Checkpoint` 与 `WIP on …` 的 stash 残骸） |
| 2026-10-10～13 | 15 | 同上（分支中间态，工作已由别的路径交付） |
| 2026-10-16 | 3 | `frontend-art-direction` 改写前的旧副本 |
| **2026-10-24** | **1** | **`ccc3886`——唯一的真孤儿** |

根因：分支的**中间态**本来就从未作为完整状态存在于 main，但它的工作早已交付。所以「树不在 main 里」单用不行，需要水位线。

### 前置已解除

`ccc3886`（3847 行的前端工作，含音频合成器、四个 overlay、存储服务、214 行测试）已于 2026-10-25 打 tag `archive/ccc3886-frontend-full-experience` 保存，变成可达，不再出现在 fsck 的不可达列表里。所以新判据落地后 main 上应当**退出 0**。

## 实现要点

- **别用 patch-id 代替树判据。** squash 与 rebase 都会改 patch-id，而树不变——`ccc3886` 那类「分支整条没合」用两者都能抓，但正常交付会用 patch-id 误报。树是这里唯一稳的量。
- 报红时打印**提交列表本身**，不要只给个数。旧口径打了计数，看的人还得自己去翻 484 个。
- 顺带把这条教训写进脚本头注：**对账与验收优先用内容判据（树、对象、逐字节），不用计数或结构判据。** 这是本路线第二次撞上同一类问题——上一次是收尾删分支：`git branch -d` 用「是否 main 的祖先」这个结构判据，在 squash + rebase 下永远通不过（见 §6.3.7）。
- 本票改的是 `scripts/`，不在快速通道内，按 §6 走 spec 分支 + ticket 分支。

## 影响面

改完之前，`npm run check:delivery` 在 main 上**是红的**（484 > 479）。落地前如果有人要交付，用 `--unreachable-baseline <实测值>` 逃逸，并在提交信息里写明为什么放过——S2 交付就是这么做的。
