# 法盘状态编码与标记层整改

## 目标

让玩家不读文字就能看懂盘面：这是谁的盘、哪一侧处于哪一档、哪些节点已归一 / 亢极、这次能打哪里、打下去会变成什么。决策依据与三处被拍死的取舍见 `docs/adr/0018-board-state-encoding-channels.md`；盘面接口契约归 `docs/LLD.md` §4.1，本文不复述。

## 背景

工单 08（`.scratch/frontend-design/issues/08-board-clarity.md`）把等级绑在色相上，并删掉归一外圈与候选连线以减噪。这一轮画面复查发现三处误读——图例四个样例全用木色、虚空与道损同为暗底、归一与亢极在盘上无标记——根因是色相通道被身份与等级同时征用。ADR 0018 重新分配了通道，本 feature 按它的落地顺序拆票。

## 实施边界

- 只改表现层。核心规则、AI、确定性随机源、回合生命周期与所有载荷契约不动。
- 内外环归属、外环逆时针偏移 2 格、真实生克路径保持既有契约（ADR 0015）。
- 浏览器预览与三尺寸（320×568 / 390×844 / 460×900）验收口径沿用 `.scratch/frontend-design/spec.md`，本 feature 不重复其研究依据。
- 像素取值（金环半径与线宽、归一 / 亢极外溢尺度与流光 / 涟漪周期、外环缩放比、候选呼吸周期）以代码常量为真源，本文不复制；金环间距按 `NODE_RING_OUTSET_RATIO` 避让，盘面外沿按 `NODE_AURA_OUTSET_RATIO` 预留。
- 设计修订与取舍演进见 ADR 0018 勘误（亢极改柔光涟漪、候选改半身紫染、相克改突刺、调息改漩涡）。

## 验收

- 各票验收见其 issue 文件。合起来要在三个尺寸下覆盖：16 种阴阳等级配对、归一 / 亢极 / 虚空混排，以及低位态（1 候选）、中位态未归一（2 候选）、归一非连动（3 候选 / 2 个落点）三种决策局面。
- 运行 `check:quick`、`build:minigame`，`verify` 通过，`minigame/game.js` 与源码逐字节对账。
- 微信开发者工具（模拟器）是**需求方（用户）的验收渠道**：用户在该工具里加载入库产物 `minigame/game.js` 目验，色号 / 形态由其拍板。agent 本机的浏览器预览只是开发自查，不算验收证据。
- 勘误：本 feature 各票早期记录里写的「微信模拟器与真机仍未跑」是 agent 的臆断（当时假定需求方没在微信里测）；事实是用户一直在微信开发者工具里测。真机（`docs/HLD.md` §4.6 第 4 步扫码 Profiling）未涉及，未声称跑过。
