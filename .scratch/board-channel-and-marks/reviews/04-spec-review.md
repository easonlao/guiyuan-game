# 票 04 Spec 轴复审

Fixed point: `8b0000a`（票 03 收尾提交）。规格：`.scratch/board-channel-and-marks/issues/04-press-preview.md` 与 `spec.md`，决策依据 `docs/adr/0018`。

## 结论

无实质缺失，未发现实现与 spec 相悖之处。

## (a) 缺失 / 部分

- 范围写「**该按钮的**候选弧加快」，实现是按住时**所有**候选一起加快（`board-view.ts` 的 `PREVIEW_BREATH_SPEED`）。这是票 03「候选同相位」硬约束下的有意取舍，已写入 ADR 0018 勘误与 issue 实施结果。不算违规。
- 截图验收（破 / 化 / 强化 / 强破 各一次）按 `spec.md` 归用户在微信开发者工具目验，issue 已正确标注为待用户拍板，agent 侧无可做。

## (b) 未被要求的改动

- `InputManager.handleTouchEnd` 改为把抬起恒定发给**按下时**命中的节点（`input-manager.ts`）。这是全局输入语义变化，超出票面字面范围，但它是「松开 / 取消 → 回到决策期」这条验收的前提（否则手指移出后抬起清不掉预览），已记录在 ADR 0018 勘误。属必要且透明的范围扩张。
- 幽灵态对吸纳 / 调息 / 散气也画（箭头条款只点名四动作，幽灵条款未限定动作类型）。与「每个按钮都预览真实净变化」一致，保留。

## (c) 重点核查项

- **真跑解析器**：`preview-target.ts` 调 `ActionResolver.resolve` 取 `nextState` 的目标节点，非近似落点；目标五行复用票 03 的 `resolveCandidateTarget`，作用侧完全交给核心。测试覆盖同侧连加、跨侧第二跳、(2,2) 净零（解析器：第一次阴 -1 后第二次重读盘面 +1 回 2，确为净零）、见底即止、`PASS`。
- **净零 / PASS**：`after === before` 返回 `null`；强破打 (-1,-1) 有路径无幽灵，与「不画幽灵态」逐字吻合（game-scene 测试有此场景）。
- **箭头几何**：相生走内环外推顺时针弧、箭尖沿切向（canvas 角度递增 = 视觉顺时针，环序 = 相生环，目标恒 +72°）；相克走跨环径向、箭尖在对方端。决策期不按住不画（箭头只在 `_preview !== null` 时绘制）。
- **共用时钟**：加速只改 `tick(dt)` 内的相位步长，`_clock` 与归一流光照常按原速推进；松开恢复原速、无相位跳变，测试断言到 9 位小数。
- `minigame/game.js` 含全部新符号，对账由构建管线保证。
