# 票 05 复审：主线程自审（两轴合一）

票 05 落地后做两轴复审。派出的两个 `Reviewer` 子代理各跑了约一小时未返回（工作区中途还被我改过，
可能让它们反复重读），改为由主线程自审，两轴合记在此。方法上比前几票多一步：**对每条设计约束做
变异测试**，逐个改坏看测试是否变红——凡是不红的，说明那条约束要么是死代码，要么测试根本没在测它。

## Spec 轴

- 外环放大到 0.92：已落地（`OPPONENT_SEAL_SCALE`）。测试断言「比值 > 0.88 且 < 1」，变异（改回 0.82）立刻变红。
- 环与相邻主印不相交：已落地，按金环外沿（`NODE_RING_OUTSET_RATIO`）预留而非 `NODE_AURA_OUTSET_RATIO`——
  理由见 `resize` 的注释与 ADR 0018 勘误（金环是实线，柔光交叠不算失败）。
- 不与操作栏 / 结果条重叠：已落地，上下外沿按最坏情况预留，图例外沿单独占一份。
- 三尺寸验收：320×568 / 390×844 / 460×900 均在真实 `GameScene` 上量过（见下「视觉验收」）。

### 复审中发现并已修的问题

1. **票面的验收与实现有落差，未记录**（Spec，应修）：窄屏 320×568 + 胶囊（safeTop 88）时，内容区只有
   246px 高。避让（跨环 + 盘外沿 + 图例）吃完，主印半径从 17.1 掉到 12.5——**票子要「外环主印可读」，
   最窄的屏反而更小了**。已做两件事：把「对方盘没有节点级标记」时的外沿按金环收（省下的高度归主印），
   并把该取舍写进代码注释与 ADR 勘误，留给需求方定夺。剩下的差距需要放宽 `GameScene.layoutBoard`
   给的边界或改可读性下限，不在本票范围内。

2. **非重叠断言曾是空断言**（Spec，阻断，已修）：逐对量「同环相邻 / 跨环金环不相交」时，去掉任一约束
   测试都照样绿——因为 `OUTER_RADIUS_RATIO = 0.4` 与 `minInner` 两个更大的下限一直在兼管，跨环公式
   从没成为 `max` 的获胜项。补了最紧的两档可用高度（150 / 130）后，跨环公式才真正被选中，变异随即变红。
   **教训：新增约束必须配一条能让它「赢得 max」的用例，否则测的是别人的功劳。**

## Standards 轴

- 单点化：像素值全部收敛到常量（`NODE_RING_OUTSET_RATIO` / `LEGEND_*` / `BOARD_*`），`_drawGuiYuanLegend`
  与 `resize` 共用同一组 `LEGEND_*`，不再各存一份 1.9 / 0.55 / 11。
- 测试里不再手抄缩放比：原先断言里的 `0.82` 魔数（突刺 / 冲击波用例）已改成 import `OPPONENT_SEAL_SCALE`，
  否则常量一改这些断言就静默失真。
- 删掉了两处**自己写出来的死代码**（变异测试暴露）：
  - `RING_OUTSET_PER_CHORD`（同环弦长公式）：在任何视口下都取不到 `max`，是死代码。已删，同环不相交
    改由「环半径比例 + 可读性下限」两个真正生效的下限保证，并在注释里写明为什么不再单列。
  - `dimensions` 返回的 `width` 字段：横向越界从未发生过（外环半径按短边 0.4 算，恒小于半宽），
    约束是死的。已删，横向改由注释说明 + 测试钉住实际投影。
- 注释：解释「为什么」，不重述代码；三处「为什么不用更大的口径」都写了理由。
