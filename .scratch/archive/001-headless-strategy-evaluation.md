## Problem Statement

归元弈的目标是成为自己和朋友愿意反复玩的简单策略游戏。玩家希望在公开棋盘、轮流行动的条件下，通过判断对手意图形成对抗，而不是通过增加操作、资源或需要记忆的规则来增加复杂度。

现有规则已有吸纳、调息、化、破、强化和强破，以及归一获胜和回合上限后的比分结算，但缺少证据判断现有取舍是否有意义、计分调整是否改善了对抗。动作使用更平均、比分更接近或对局更长，都不能单独证明博弈变深。

目前测试主要覆盖节点状态与基础增减。完整对局还依赖动画、事件和网络流程，难以低成本、可复现地比较规则版本。现有 AI 的动作评分也不能作为唯一评价标准，否则可能把“更符合该评分器偏好”误当成“更有博弈性”。

## Solution

提供一个复用正式规则的无界面对局接口，以及基于该接口运行的策略评估工具。

输入初始局面、规则配置、随机种子或指定天干序列和双方策略，输出行动记录、最终胜负和评估统计。使用相同实验条件比较当前计分基线和实验计分版本，并交换先后手及策略角色。

评价分为两类：

- 规则正确性：动作、消耗、状态边界、额外行动、结算和胜负等外部行为，使用确定性测试作为硬断言。
- 博弈效果：固定局面和批量完整对局产生比较报告，寻找可靠的“应对交叉”，检查简单策略是否普遍占优，以及攻击是否造成循环压制。首版不设置未经验证的平衡通过阈值。

“应对交叉”指同一局面、同一当前天干下，面对不同对手策略，至少两个候选动作的后续胜负价值排序发生有实质意义的反转。例如面对偏建设对手时攻击更好，面对偏攻击对手时建设更好。该现象只能支持在已测局面和策略范围内存在条件性取舍，不能证明全局最优或真人一定觉得好玩。

用户已确认主要测试边界：无界面对局接口，不另写一套模拟规则，不依赖动画或网络。

## User Stories

1. As a 游戏设计者, I want 在不新增玩家操作和记忆规则的前提下评价现有动作, so that 我能改善简单规则内的对抗。
2. As a 游戏设计者, I want 保持随机天干机制和胜利条件不变, so that 首轮实验能够集中评价计分的影响。
3. As a 游戏设计者, I want 保存当前规则作为明确的基线, so that 实验结果有可比较的参照。
4. As a 游戏设计者, I want 使用独立命名的实验计分配置, so that 未验证方案不会直接影响正式游戏。
5. As a 游戏设计者, I want 单独比较计分变动及其组合, so that 我能识别哪些变动带来了效果。
6. As a 开发者, I want 无需浏览器、动画和网络运行对局, so that 我能快速重复实验。
7. As a 开发者, I want 无界面与正式游戏共用动作及回合规则, so that 自动化结论对应真实游戏。
8. As a 开发者, I want 从完整初始局面启动实验, so that 我能检查特定发展阶段的取舍。
9. As a 开发者, I want 指定当前玩家、当前天干和额外行动状态, so that 固定局面测试不遗漏回合语义。
10. As a 开发者, I want 通过随机种子或指定天干序列重放对局, so that 我能复现意外结果。
11. As a 开发者, I want 策略只能看到玩家可见信息和合法动作, so that 评估不会依靠偷看未来随机结果。
12. As a 开发者, I want 每局状态和规则配置互不污染, so that 批量结果不取决于执行顺序。
13. As a 开发者, I want 吸纳、无法行动和非法策略选择有明确处理, so that 模拟器不会默默修正错误输入。
14. As a 开发者, I want 验证强化和强破的消耗、两次效果和额外行动, so that 完整对局准确反映这些关键取舍。
15. As a 开发者, I want 验证亢极分红、道损亏损及实际启用的最终结算, so that 比分胜负不会被模拟遗漏影响。
16. As a 开发者, I want 明确回合上限与额外行动的计数时机, so that 比较不会隐藏边界差异。
17. As a 游戏设计者, I want 面对偏建设、偏攻击和局势响应型策略进行比较, so that 我不会只针对一种对手优化。
18. As a 游戏设计者, I want 在固定局面枚举全部合法首步, so that 我能比较真实选择而非 AI 已经选定的动作。
19. As a 游戏设计者, I want 根据完整对局的最终胜负评价动作, so that 即时得分不会替代真正的目标。
20. As a 游戏设计者, I want 查看动作排序随对手策略变化的证据, so that 我能判断猜对手是否有价值。
21. As a 游戏设计者, I want 看到样本数、差值和不确定性, so that 小幅随机波动不会被包装成应对交叉。
22. As a 游戏设计者, I want 覆盖均势、领先落后和临近回合上限的局面, so that 结论不只来自一个精心挑选的例子。
23. As a 游戏设计者, I want 区分可达局面与人为诊断局面, so that 我知道证据能否代表实际对局。
24. As a 游戏设计者, I want 对新旧版本使用相同随机样本并轮换先后手, so that 我能降低随机和先手因素的混淆。
25. As a 游戏设计者, I want 查看策略对阵胜负矩阵, so that 我能发现是否存在普遍占优的简单打法。
26. As a 游戏设计者, I want 查看对局长度、重复棋盘和胜利方式分布, so that 攻击增强不会以循环修补为代价。
27. As a 游戏设计者, I want 从统计结果追溯完整行动记录, so that 我能解释异常胜率和反复压制。
28. As a 开发者, I want 通过命令运行小规模默认评估并扩大样本, so that 日常验证可用且深入实验可扩展。
29. As a 开发者, I want 获得机器可读结果和简明的人类报告, so that 我能进行后续比较并向玩家解释发现。
30. As a 游戏设计者, I want 报告明确没有发现交叉或证据不足的情况, so that 工具不会强行宣布方案成功。
31. As a 试玩组织者, I want 获得值得真人复核的局面与行动分歧, so that 我能进一步检查玩家是否理解和利用取舍。

## Implementation Decisions

- 首版交付评估能力，而不是直接发布平衡调整。默认正式游戏保持现有规则；实验配置只通过显式选择生效。
- 主要公共边界是无界面对局接口：接受完整局面、随机输入、规则配置和双方策略，返回状态轨迹、行动记录及终局结果；支持固定首步后的完整续局评估。评估工具围绕这一个边界组织。
- 优先复用现有候选动作计算、动作结算、计分和下一玩家判定。对耦合展示的回合及终局逻辑做最小必要抽离，由正式流程和无界面流程共用；不得在评估器内维护平行规则实现。
- 核心运行不导入展示、网络、存储或学习记录等副作用模块，不通过伪造 DOM、等待动画或完整事件总线流程来获得无界面对局。
- 若现有共享状态暂时仍为单例，首版可顺序运行，但每局、每个动作分支和每次规则切换必须完整重置或隔离。不得承诺未经验证的并发运行。
- 完整局面包含阴阳节点值、积分、当前玩家、当前天干、回合计数、上限、额外行动及影响后续规则的其他状态。输入校验明确错误，不静默填补影响胜负的缺失值。
- 实际候选动作是策略选择的唯一合法来源。自动吸纳不作为可自由选择的动作；合法动作为空时依正式规则跳过；策略返回非法动作应报错并保留复现信息。
- 随机天干保留现有概率语义。实现可重放的种子随机源，另支持指定天干序列；随机策略的平局选择使用独立随机流，不改变天干流。
- 固定天干流按实际行动机会顺序消耗，包含额外行动。规则或策略分歧可能改变接收某个天干的玩家；报告说明配对随机样本不代表双方获得了完全相同的个人机会。序列耗尽应明确失败，不偷偷转入随机模式。
- 策略可见信息仅包含公开局面、已发生历史、当前天干与合法动作，不包含未来天干、对手内部参数或实验标签。实验调度器知道对手策略类型不等于玩家策略可以偷看类型。
- 策略至少包含建设优先、攻击优先和局势响应型，并有清楚、确定的规则与合法回退。策略对不同计分配置维持同一套决策定义；若引入配置感知版本，须独立命名并分别报告。
- 不以现有 AI 动作评分作为胜负评价函数。可将现有 AI 作为附加对照，但不是唯一对手或正确性裁判。
- 固定局面实验枚举全部合法首步，使用相同续局策略、样本和明确的策略身份比较。结果是该续局假设下的动作价值估计，不称为全局最优动作。
- 胜负价值统一使用胜利为 1、平局为 0.5、失败为 0，同时独立报告胜、平、负比例。积分与归一变化作为解释指标，不替代终局目标。若采用截断续局，只能单独报告代理指标，不混入完整对局胜负。
- 应对交叉要求两种动作面对两种对手时价值差的符号反转，并达到预先声明的最小效果量与统计证据要求。参数随实验配置记录，不在看到结果后调整以制造成功；该证据门槛不是新版必须通过的产品平衡阈值。
- 对配对种子的动作价值差提供可复现的不确定性估计。探索样本发现的交叉应在独立确认种子上复核；报告分开呈现探索与确认结果，并说明多局面搜索带来的选择偏差。
- 初始局面至少覆盖双方发展接近、一方领先另一方需干扰、临近回合上限三类。优先从基线完整对局记录抽取可达局面，并冻结该集合用于版本比较；手工局面单独标为诊断样本。
- 比较基线和候选配置时，每场双方均使用该场相同规则版本，不让双方在同局使用不同计分。对阵覆盖策略互换和先后手互换，保存实际初始状态与随机输入。
- 计分实验支持独立配置化的三个候选维度：自损不按攻击状态变化奖励；强化与强破的行为分按整次动作而非成功子步骤重复累计；禁用稀有度加成。它们是待验证假设，不是已确认的正式修改。
- 当前计分行为必须先建立特征测试，包括自损仍获得正分、子步骤累计行为分以及稀有度计算。只调整计分配置时，同一初始状态和同一合法动作记录的棋盘变化及额外行动语义保持一致；允许终局比分不同。
- 棋盘重复指标使用双方节点、当前玩家和额外行动状态构成的键，并说明没有包含积分、回合数和随机流位置，因此只能表示重复棋盘结构，不能据此证明严格无限循环。正式回合上限仍照常结束对局。
- 记录动作频率、完整对局长度、重复棋盘次数、归一获胜与回合上限比分结算比例，以及双方推进与破坏轨迹。首版将这些用于诊断，不将“更均衡”或“更长”直接解释为更好。
- 结果包含规则配置快照与版本身份、策略定义身份、局面身份、种子、样本数、先后手、实验参数、胜负矩阵、不确定性和可重放案例。人类报告区分事实、有限范围推断和待真人验证项。
- 提供项目命令入口，支持小规模默认运行、样本数和种子设置、输出位置及规则配置选择；配置非法、无法终局或运行错误返回非零退出状态。未发现交叉或候选表现下降仍输出正常报告，不当作工具执行失败。
- 若运行受样本预算限制、出现失败或跳过对局，必须明确报告计划数量、完成数量、缺失原因和覆盖范围；不得将失败样本当作平局或静默删除后宣称完整覆盖。

## Testing Decisions

- 好的测试通过无界面对局的输入与输出断言外部行为，不断言私有方法调用顺序、动画事件数量或内部模块布局。
- 既有 Vitest 节点状态与动作增减测试是测试框架及归一、亢极边界的先例；保留这些测试，并在更高的对局边界补齐完整流程覆盖。
- 规则回归覆盖六类动作、状态上下界、阴阳优先级、源节点消耗、部分效果达到边界、自动吸纳、无合法动作、非法输入和合法行动校验。
- 回合回归覆盖普通轮换、强化及强破后的额外行动、额外行动中再次强化不能无限连动、回合计数、上限临界点及积分结算顺序。
- 终局回归覆盖双方五行归一获胜、回合上限比分胜负及平局；终局后不继续消耗天干或执行动作。
- 计分回归覆盖行为分、状态分、稀有度、亢极分红和实际启用的道损结算；区分节点一侧道损与结算当前采用的整节点条件。
- 在抽离前建立当前行为的特征用例，并在正式流程的逻辑适配入口和无界面入口使用相同用例验证等价性。展示和网络副作用不属于该等价性断言。
- 静态阅读发现当前联机主机结束回合会结算被动分，而单机结束回合路径未见同一调用。实现时须明确记录差异：本工具以面向朋友对战的联机主机规则语义为主要基线；抽离不得顺手改变单机行为或将差异隐去。
- 最终道损惩罚存在辅助实现，但其实际启用时机不能仅凭函数存在认定；基线按真实调用路径建立特征测试，不自行补上规则说明中的行为。
- 验证相同配置、种子、初始局面和策略得到相同记录；验证指定天干序列消耗包含额外行动、耗尽报错，以及多局运行不互相污染。
- 验证策略看不到未来随机输入，且策略随机流不改变天干流。
- 对报告与统计使用可人工核算的输入，验证胜平负、平局权重、角色交换、配对差、样本数、重复键、失败样本和配置身份。
- 对交叉检测器使用人工构造的动作收益数据，验证真实反转、无反转、效果量不足和不确定性不足等分类。该测试验证检测器，不要求真实游戏必须产生交叉。
- 提供端到端小规模评估冒烟测试，验证基线和实验配置均能完成完整对局并生成可重放报告；不把短批次中的胜率或交叉数量当作稳定回归断言。
- 对真实游戏进行探索与独立确认实验。没有发现应对交叉是有效研究结果，应报告而不是使规则测试失败。
- 完成后运行项目现有测试与构建，确认必要的共享逻辑抽离未破坏正式应用的加载与构建。

## Out of Scope

- 直接替换正式计分，宣布某个候选方案已经更好，或提交未经比较的平衡数值。
- 改变随机天干分布、胜利条件、玩家操作数量、动作目标选择方式，或增加暗牌、同时出招、资源、技能与隐藏信息。
- 顺手修复所有当前单机与联机规则差异；这些差异须记录并保持明确的评估基线。
- 重写整套游戏架构、引入多份规则引擎或为模拟器复制动作及回合算法。
- 联机同步、重连、排行榜、存储、教程、动画和浏览器端到端质量验证。
- 训练新 AI、求解全局最优策略、穷举整个状态空间，或证明任意玩家都不存在优势套路。
- 大规模默认实验、分布式并发运行和性能排行榜。
- 自动证明真人能够理解取舍、猜对对手或愿意重玩；这些仍需要真人试玩。

## Further Notes

- 完成标准是可用、可复现、可信地报告证据，不是必须证明当前候选计分更优。
- 理想候选应在确认样本中展示应对交叉，且没有明显增加重复压制或削弱推进。但“明显”的产品容忍度需根据基线报告和真人体验在后续任务中确定，首版不伪造通用数值标准。
- 玩家对抗的最终验证问题是：判断对手打法是否改变我的选择；判断正确是否带来优势；攻击后是否仍有可推进的路线。
- 当前领域术语以归一（两侧至少为1）、亢极（两侧都为2）、道损（单侧为-1）为准。现有实现中部分局部变量和注释混用术语，报告应使用规范词汇，不借此修改动作资格条件。
- 规格生成时未发现现有 ADR 目录或本地问题记录；这不意味着项目不存在其他设计约束或已知故障。
