# 回合上限结算输方 500 分诊断说明

- **关联 Issue**: [01: 回合上限结算输方 500 分诊断](../../.scratch/balance-diagnostics/issues/01-loser-score-floor-diagnostic.md)
- **诊断日期**: 2026-10-06
- **诊断结论**: 
  - **已证实**: 500 分不是保底分、下限钳制或记录口径错误，而是 `maxTurns=12` 截断与固定种子（202603/202604）组合下的虚假假象。
  - **已证实**: 计分体系存在显著的滚雪球机制（`BURST` 强化动作包含 3 项高额子步骤加分 + 稀有度加成 + 额外行动回合）。
  - **已证实**: 在正式游戏 `maxTurns=60` 下，输方恒为 500 分的现象完全消失，终局表现呈现正常的离散分布与五行归元获胜。

---

## 1. 500 分的精确来源与代码行号

在 `maxTurns=12` 的批量评估中，输方（种子 202603 中的 P1，种子 202604 中的 P2）终局得分恒为 500。其精确形成机制如下：

1. **回合截断机制** (`src/js/logic/flow/TurnRules.js:99-104`, `HeadlessMatch.js:389-398`):
   - 在第 12 回合开始前，`decideTurnStart` 发现 `turnCount >= maxTurns (12)`，立即判定终局（`reason: '回合上限'`）。
   - 实际完成的有效行动回合恰好为 11 个机会点（Opportunity 1..11）。
2. **行动分配与先手影响**:
   - 当无连续回合时，先手方分配到 6 个回合（1, 3, 5, 7, 9, 11），后手方分配到 5 个回合（2, 4, 6, 8, 10）。
   - 在后手方发动 `BURST` 获得额外回合时，后手方占用连续机会点，导致另一方总计仅获得 5 个行动机会。
3. **强制吸纳无决策** (`src/js/logic/headless/HeadlessMatch.js:428-430`):
   - 当随机摸到的天干对应的阴/阳侧数值 `< 1` 时，规则强制执行 `AUTO`（吸纳），不调用策略选择：
     ```javascript
     if (currentSideValue < 1) {
       action = { type: 'AUTO', executorId: playerId, playerId, stem: clone(stem), isYang };
       availableActions = [clone(action)];
     }
     ```
   - 在测试种子中，输方的 5 次摸牌全部落在初始值为 0 的未点亮侧，全部被强制执行 `AUTO`，决策次数为 0。
4. **单次 AUTO 计分拆解**:
   - **行为分**: `POINTS_CONFIG.ACTION.AUTO = 0` (`src/js/config/game-config.js:54`)。
   - **状态分**: 点亮状态分 `POINTS_CONFIG.STATE_CHANGE.LIGHT_UP = 100` (`src/js/config/game-config.js:66`, `ScoreCalculator.js:98-100`)。
   - **稀有度加成**: `ACTION_PROBABILITY.AUTO = 1.0` (`src/js/logic/actions/RarityScoring.js:5`)，稀有度加成系数 `(1 - 1.0) * 1.5 = 0`。
   - **最终单步得分**: `0 + 100 = 100`。
5. **输方总分**:
   - 5 次强制吸纳 × 100 分 = **500 分**。
   - 全程没有经历加持、调息、破、强破或化，亦未触发任何惩罚或持续分红。

## 3. 领先方滚雪球效应分析与最小复现

### 滚雪球机制确认
已证实计分与规则设计包含强正反馈（滚雪球效应）：
1. **BURST 的高额复合收益**:
   - `BURST` 动作本身具有极低先验频率（`ACTION_PROBABILITY.BURST = 0.035`），稀有度放大乘数高达 `(1 - 0.035) * 1.5 = 1.4475`。
   - `BURST` 的执行分步骤触发破坏旧侧、点亮新侧、加持新侧 3 次状态变化，全部叠加稀有度放大，单次动作产生 1616 分。
2. **额外行动机制**:
   - `BURST` 触发 `isExtraTurn = true`，使领先方立即再摸一张天干并行动，进一步拉大局势差距。
3. **持续分红 (UNITY_DIVIDEND)**:
   - 一旦达到归一 (2, 2)，每回合被动获得 +50 分分红。

### 最小复现例
- 运行 `runSeededMatch({ initialState: createInitialHeadlessState({ maxTurns: 12 }), seed: 202603, strategies: { P1: 'build-priority', P2: 'build-priority' } })`
- 在 Opp 10，P2 执行一次 `BURST`：
  - 分数从 637 飙升至 2253（净增 1616 分）。
  - 并获得 Opp 11 额外行动，再度执行吸纳达到 2353。

## 4. 60 回合正式规则复查

当将 `maxTurns` 恢复为正式规则的 60 时：
1. **五行归元正常发生**:
   - 在种子 `202603` 对局中，双方至第 21 个行动时，P2 达成"所有天干点亮"（五行归元），以 8789 分胜出（P1 得分 9978 分，说明五行归元优于分数结算）。
2. **输方得分不再恒定**:
   - 在未达成五行归元、进入 60 回合上限结算的对局中，输方得分分布在 4,159 ～ 13,246 之间，胜方得分分布在 5,668 ～ 16,546 之间。
   - 输方恒为 500 分的假象彻底消除。

## 5. 诊断结论一览

| 诊断项 | 结论判定 | 说明 |
|:---|:---:|:---|
| 500 分是否为代码硬编码底分/下限 | **已证伪** | 配置与代码中无任何 500 分保底逻辑。 |
| 500 分是否为 12 回合截断与种子巧合 | **已证实** | 5 次强制吸纳 × 100 分 = 500 分。 |
| 计分系统是否存在滚雪球机制 | **已证实** | BURST 多重状态加分、高额稀有度乘数及额外行动回合造成巨大领先优势。 |
| 60 回合下 500 分现象是否存在 | **已证伪** | 60 回合下输方得分正常离散分布，且大量对局以五行归元直接获胜。 |
| 是否需修改正式计分 | **否（第一阶段）** | 遵照 PRD 决策，第一阶段不修改正式计分，先完成测量工具修正与扫描。 |
