# 02: 让占优守卫真的检测占优 (Make the Dominance Guard Real)

**What to build:** 让「占优结论必须被矩阵支撑」这条守卫真正做到它名字说的事。

现状：该守卫只在报告排版时检查「矩阵存在、且结论里点名的对手出现在矩阵里」。它不读胜率，不判断占优是否成立，因此一个与矩阵矛盾的占优结论可以照常打印。它自己的测试也只用手写的两格假矩阵，验证「缺矩阵时抛错」。

本票要让它校验结论与数据一致：从矩阵重新计算每个被点名对手的座次平衡胜率，确认结论里声称的占优确实成立；不成立就拒绝输出。ADR 0011 的「后果」把这条守卫当作改计分后的执行机制——本票是让那个机制变成真的。

顺带要处理临界格：本轮已有格子落在统计上与 50% 无法区分的位置（归元冲刺 ↔ 纯推进 的 board-only 50.21%）。守卫不应把这种格子当作占优证据。

**Blocked by:** None (can start immediately)

**Status:** closed

- [x] 守卫从矩阵重算，校验结论声称的每一对占优都确实成立
- [x] 结论与矩阵矛盾时拒绝输出，错误信息指出是哪一对、矩阵里的实际值是多少
- [x] 矩阵缺格、样本不足、或无法判定时明确拒绝，不静默通过
- [x] 临界格（与 50% 无法区分）被标为不可判定，不能作为占优证据
- [x] 回归测试覆盖四种情形：真结论通过、假结论被拒、缺格被拒、临界格不可判定
- [x] 现有依赖该守卫的测试与报告生成路径全部仍通过

**完成：** 提交 `479cdd0`。判定逻辑集中在 `evaluateDominanceEvidence`（`src/core/headless/Metrics.ts`），谓词与断言共用。阈值 z=1.96（双侧 95% / 单侧 97.5%），最小样本 100。

代码评审发现并修复：`computeDominanceVerdicts` 原本把无法判定的配对**静默过滤**，于是「样本不足」的报告会读作「没有占优」——正是本审计要消灭的失败模式。现改为显式报出不可判定配对数与原因，并有回归测试锁定。端到端验证：10 局/座次时输出「本对拼矩阵无法判定是否存在严格占优：不可判定 42 对（样本不足 42 对），不能据此断言「无占优」」。
