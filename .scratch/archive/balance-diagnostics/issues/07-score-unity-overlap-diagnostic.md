## Agent Brief

**Category:** enhancement
**Summary:** 建立一个诊断测试并生成报告，在60回合上限下验证计分与五行归元进度的重合度。

**Current behavior:**
目前存在一个未经验证的假设：游戏的正式计分与五行归元（Unity）进度高度重合，计分没有形成独立的博弈路线。虽然 `POINTS_CONFIG` 中建设类得分明显高于攻击类，但目前缺乏实测数据支撑，无法为第二阶段计分调整提供基线依据。

**Desired behavior:**
开发并运行一个只测量、不改规则的自动化诊断测试，输出基于数据的分析报告。测试需沿用第一阶段 60 回合的对阵组合，运行 ≥200 个随机种子并交换先手。测试需要收集并汇总：
1. 回合上限结算时，分高者与点亮侧数多者是否一致的比例（含相同占比），并按对阵组合列出。
2. 胜方和输方的得分结构拆分：建设（点亮/加持/修复道损）、攻击（致道损/破点亮/削弱加持）、行为分、亢极分红、道损扣分、稀有度加成。
3. 第 30 回合（中盘）分数领先方与点亮领先方的一致性，以及在一致和不一致时各自的终局结果。
结果必须以 markdown 形式写入 `artifacts/balance-diagnostics/`，且内容按“问题—证据—边界”组织。允许出现“证据不足”的结论。

**Key interfaces:**
- `POINTS_CONFIG` (位于 `src/js/config/game-config.js`)：需要基于现有正式配置计算。
- 状态记录：利用 `StateScoreRecorder` 等现有统计机制或者在测试运行器中拦截抓取各维度的得分明细和节点状态（如点亮数）。
- 自动化测试与输出：复用或扩展第一阶段的诊断测试脚本，执行特定对决后汇总指标。

**Acceptance criteria:**
- [x] 在 60 回合上限下，沿用第一阶段对阵组合，运行 ≥200 种子并交换先手。
- [x] 统计并报告终局时“分数高者 = 点亮侧数多者”的一致性比例及同点亮占比。
- [x] 将每局得分正确拆分为建设、攻击、行为分、亢极分红、道损扣分、稀有度加成等来源，分别报告胜负方构成。
- [x] 统计第 30 回合状态，并输出分数/点亮领先方是否一致对终局结果的预测情况。
- [x] 成功在 `artifacts/balance-diagnostics/` 目录下生成 Markdown 报告，组织结构包含“问题”、“证据”和“边界”。
- [x] 完全不修改游戏的正式规则或正式计分逻辑。

**Out of scope:**
- 任何对游戏核心逻辑（点亮、加持、虚空、道损等流转）的修改。
- 任何对 `POINTS_CONFIG` 数值的修改（仅限读取与统计）。
- 开发超过两步防守深度的更强 AI。
