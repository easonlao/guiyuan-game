用户确认 `a2cde20` 上人物已经正常显示。真实微信日志表明，包内路径 `assets/characters.png` 的原生 Image 加载先触发 error；随后 readFile 读取 1613898 字节、PNG magic 正常，writeFile 写入 `http://usr/guiyuan-characters.png` 成功，缓存绝对路径图片通过 onload，报告自然尺寸 1254×1254。旧加载顺序因此在最终成功时仍留下红色错误。用户要求修复这条错误。

## 实施结果

- 当文件系统与 USER_DATA_PATH 可用时，启动直接执行读取、签名检查、缓存写入，然后用新微信图片对象加载已确认可用的缓存绝对路径。正常启动不再尝试会失败的包内 Image.src。
- 文件读取、PNG 签名/最小长度检查、缓存写入或缓存解码失败时，明确记录警告并至多回落包内图片路径一次。只有所有可用方案失败才输出 console.error；未全局屏蔽错误或把未解码图片启用。
- 缺失缓存能力的宿主继续直接加载，无常规 API 缺失警告。保留图片强引用、回调解绑、成功 onload 门槛以及自然尺寸兼容。
- 使用统一读取/写入/缓存加载/包内加载/完成阶段门槛，屏蔽迟到、重复和交错回调，避免多次加载或已成功图集被过期失败清除。
- 人物素材、游戏入口、角色动作及微信顶部布局未修改。
