# 精致卡通人物素材与双宿主加载

状态：已完成。

## 用户目标

用户认为第一版程序绘制人物呆板，选择保留夸张比例、增加个性和细节的精致卡通方向。本票将通过人物素材替换程序轮廓，保持已有对局与七态反馈。

## 范围

- 制作双方七态的透明人物图集，统一墨青、玉色与暖金的修仙美术方向。
- CharacterView 显式接收已加载的 Canvas 图片；微信与浏览器宿主分别加载同一入库素材。
- 依据素材真实裁切矩形绘制对应玩家与姿态，保持比例、呼吸和跳跃，完整显示于现有头像框。
- 素材未加载或加载失败时继续使用现有角色绘制，避免角色空白。
- 不调整玩法规则、选项动画映射与对局生命周期。

## 验收

- 核查双方 idle、attack、hurt、cast、celebrate、win、lose 的图集帧映射。
- 测试素材注入前后的绘制分支、等比缩放与头像框边界。
- 用真实 Canvas 在 320×568、390×844、460×900 与14态人物画廊检查可见性。
- 执行 check:quick、build:minigame、verify，并记录微信真机验证限制。

## 实施结果

- 新增 `minigame/assets/characters.png`，1254×1254 透明 RGBA 图集，1637564 字节。弈者为墨发玉绿袍，天道为银发云白袍；双方各七态，采用精致卡通比例、眼神、发束、金饰与服装纹样。
- 新增 `src/minigame/character-sprite.ts`，管理共享素材路径、14 个精确内容裁切矩形与脚底基线；按每方完整姿态集合计算统一比例，避免攻击宽袖导致身体随状态缩小，并保留呼吸、出掌上提、受击下挫与庆祝跳跃。
- CharacterView 显式接收解码后的图集。微信入口通过 wx.createImage，浏览器预览通过 Image 加载同一入库文件；浏览器 Vite 将静态 URL 解析为该文件的 /@fs 路径，实测 HTTP 200、正常解码。
- 图片未完成加载或加载失败时保留已有程序角色。GameScene、核心规则与选项到七态的映射维持原契约。

## 实际验收

- 新增 7 项素材测试：14 态帧选择、等比缩放、显式裁切、共有身体比例与脚底锚定、最终图集裁切/头像边界、成功加载与失败回退、无效尺寸回退。加原人物测试共 24 项专项通过。
- `build:minigame` 重建 game.js，166166 字节；最终 `verify` 全部通过：50 个测试文件、903 项测试，格式、lint、类型、包边界、依赖边界与产物逐字节对账全部通过。`git diff --check` 通过。
- Explore 在真实宿主检查 320×568、390×844、460×900 和双方全部七态，无裁切、邻帧残影、姿态切换缩放或浏览器运行时错误。原画身体在屏幕约 P1 84px / P2 78px，受击与败态因弯身自然较短；最细五官在原生小尺寸仍较细。
- 实际截图：不入库的 `artifacts/ui-design/character-refined-{320,390,460}.png` 与 `character-refined-states.png`。
