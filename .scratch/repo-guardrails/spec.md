# Spec: 治我那三类错，顺带瘦身 AGENTS.md (repo-guardrails)

## Problem Statement

2026-10-25 那轮清理里，我犯了三类错，反复出现：

| 类 | 表现 | 实例 |
|---|---|---|
| **采样当全量** | 用 `head`、`grep -c` 的结果当完整事实 | 说 5 个合并提交（实际 40）；说 32 个文件（实际 15）；说 18 处引用（实际 22） |
| **判据选错** | 用计数或结构做判断，该比内容 | 四次：`branch -d` 按祖先关系、棘轮按数量、棘轮按 `main` 比、只按内容判（34 命中 33 假阳） |
| **机械替换不复核** | 正则批量替换后只看了首尾 | 产出「原 报告层（已删）」这类嵌套括注，还吃掉了 `§4.1` 只剩 `/§4.5` |

同时 `AGENTS.md` 涨到 102 行：指针分散在 6 个 `###` 小节里，还有已经在讲「已删目录」的沉降层。

## 决定

1. **不是二选一，按错的类型分工。** 可枚举的事实交给脚本（A 类错误的根），判断质量交给提问（B 类）。C 类只能靠「改完逐行过 diff」，不进门禁。
2. **只断言不变式，不锁快照数字。** 锁数字会造跑步机——`check:delivery` 断言③ 已经翻过这车（见票 05）。所以新脚本里一条固定数字都不锁。
3. **不新增 `pre-commit` hook。** 仓库明写「没有 `pre-commit` hook，拦截靠交付前的本地验收」（`CONTRIBUTING.md` §1）。新检查进 `check:quick`，效果相同且不引入一类新的失败面。
4. **`AGENTS.md` 按写作杠杆瘦身**，不按字数删：指针合并成一张带触发条件的表（一个触发一个分支），删掉已被别处承载的复述，加三条提问。
5. **三条提问用正面表述 + 一个领头词**（全量 / 比内容 / 红），写在 `AGENTS.md` 的「报告之前」——报告是错的暴露点。
