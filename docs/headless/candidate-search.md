## 1. 判据（缺一不可）

四条标准由 spec 定义，`validateCandidate` 一次跑完并同时报告：

1. **无严格占优** —— 对拼矩阵中不存在对全部对手严格占优的策略，**且矩阵完全可判定**
   （z = 1.96 的显著性证据，每格 ≥ 100 局）。矩阵缺格 / 样本不足 / 有与 50% 无法区分的对时，
   标准 1 记「**无法判定**」而不是「通过」：缺格或样本不足的矩阵不能断言「无占优」。
2. **每个行为都有价值** —— 动作价值普查中没有在所有被测盘面上都被支配的动作。
3. **护栏全绿** —— 500 局平衡自对弈、种子 10000、回合上限 30：归元率 ∈ [0.75, 0.95]、
   先手胜率 ∈ [0.45, 0.55]、堆内存增量 < 15MB。流局率始终与先后手胜率成对报告。
4. **动态策略打赢全部静态预设** —— 动态切换策略对全部 7 个静态预设的座次平衡胜率**显著**高于 50%
   （95% CI 下界 > 50%，不是裸 > 50%）。

## 3. 被采纳候选 A：进度定价

### 3.1 机制

`PointsConfig` 新增可选字段：

```ts
readonly ATTACK_PROGRESS_SCALE?: { readonly floor: number; readonly span: number };
```

作用点：`ActionResolver` 的 **ATK / BURST_ATK 分支**。攻击状态分
（`calculateTransitionPoints(..., isAttack = true)` 的返回值，即 `CAUSE_DMG` / `BREAK_LIGHT` /
`WEAKEN`）乘以

```
factor = floor + span × (countBoardGuiYi(行动前对手盘面) / 5)
```

四舍五入取整。`countBoardGuiYi` 取**行动前**的对手盘面（`state.players[opponent].board`）。
系数从 0.3（对手 0 个归一节点）到**有效上限 1.02**（对手 4 个归一节点）；`countBoardGuiYi === 5` 等价于该方已达成五行归元、对局当场判定（`State.ts:70,239`、`ActionResolver.ts:326,352-353,368-369`），故行动时对手最多 4 个。1.2 只在揭牌分支可达（对手已锁定归元、己方听牌揭牌）。**过零点**在 `0.3 + 0.9n/5 = 1` ⇒ `n ≈ 3.89`：对手 0–3 个归一节点是打折，只有 4 个才是加成。

**不缩放**：`ACTION.ATK` / `ACTION.BURST_ATK` 行为分、`GUI_YI_MILESTONE`、己方建设分
（`REPAIR_DMG` / `LIGHT_UP` / `BLESSING`）。AI 估值器通过 `scoreDelta` 自动看到该变化。

生产 `POINTS_CONFIG` 已设置 `ATTACK_PROGRESS_SCALE: { floor: 0.3, span: 0.9 }`（ticket 06 采纳）；未配置时 `attackProgressScale` 返回恒等 1。

实现上把「行动前对手归一节点数」以数字传入 `ScoreCalculator.attackProgressScale(count)`，
`ScoreCalculator` 不反向读取 `GameState`；`npm run check:deps` 无循环/层级违规。

### 3.2 配套调优动态策略（dyn-v3-self7）

```ts
// src/core/headless/DynamicSwitching.ts
export const TUNED_DYNAMIC_POLICY: DynamicSwitchPolicy = {
  name: '动态切换(调优v3)',
  advanceSelfMax: 7,
  minLeadForAdvance: 0,
  advanceWhenOpponentActionsAtLeast: Infinity,
  advanceWhenLeadAtLeast: Infinity,
  shouldAdvanceWhenNoAtkTempo: false,
  shouldAdvanceWhenAtkTempoZero: true,
  advanceWeights: { ...AGGRESSIVE_WEIGHTS, repairDamage: 100, lightVoid: 100, reachGuiYi: 100, guiyuanProgress: 80 },
  suppressWeights: AGGRESSIVE_WEIGHTS
};
```

即：推进模式不再是「归元冲刺」而是「激进骨架 + 建设项 60→100 / 80」；己方还差行动 ≤ 7
或本回合最佳【破】盘面收益为 0 时切推进，否则压制。全部为既有旋钮，不新增规则开关。
它**不进入** `ALL_DYNAMIC_POLICIES`，`DEFAULT_DYNAMIC_POLICY` 保持不变。

## 4. 四条标准的复跑证据

真实测量台，候选 A + 调优动态策略，**每座次 2000 局（每格 4000 局）**，回合上限 30。

### 4.1 标准 1 — 无严格占优：通过（以完全可判定的种子 20000 为确认证据）

对拼矩阵中不存在对全部 6 个对手严格占优的策略，且矩阵完全可判定
（M = 2000/座次、种子 20000）。各策略均只占优部分对手，呈石头剪刀布结构：

- 平衡 → [归元冲刺, 激进压制, 保守自保, 纯推进, 纯压制]（5/6）
- 激进压制 → [归元冲刺, 保守自保, 纯推进, 纯压制, 剥离计分]（5/6，**输给平衡**）
- 剥离计分 → [平衡, 归元冲刺, 保守自保, 纯推进, 纯压制]（5/6）
- 保守自保 → [归元冲刺, 纯压制]（2/6）
- 纯推进 → [归元冲刺, 保守自保]（2/6）
- 纯压制 → [归元冲刺, 纯推进]（2/6）
- 归元冲刺 → 无（0/6）

**种子 10000 的矩阵对 C1 是「无法判定」**：有 1 对 within-noise
（归元冲刺 vs 保守自保，50.10%），按严格口径不能读作「无占优」。因此确认证据固定用种子
20000（完全可判定）；旧报告把该对静默当作通过，正是本次修正的失败模式。

### 4.2 标准 2 — 每个行为都有价值：通过

`runActionValueCensus` 在候选配置下 `globallyDominated = []`：

| 动作类型 | 可用 | 观测数 | 最优盘面数 | 被支配盘面数 | 全局被支配 |
| --- | --- | ---: | ---: | ---: | --- |
| AUTO | 是 | 48 | 9 | 0 | 否 |
| CONVERT | 是 | 6 | 6 | 0 | 否 |
| TRANS | 是 | 33 | 3 | 6 | 否 |
| ATK | 是 | 20 | 2 | 4 | 否 |
| BURST | 是 | 54 | 6 | 6 | 否 |
| BURST_ATK | 是 | 40 | 5 | 5 | 否 |
| DISSIPATE | 是 | 6 | 3 | 0 | 否 |
| PASS | 是 | 2 | 1 | 0 | 否 |

没有动作在所有被测盘面上都被支配。压制侧价值沿 `oppGuiYiNodes` 轴从 0.3× 到有效上限 1.02×（揭牌分支 1.2×）单调上升，
【破】在 `kangji/*` 盘面仍为最优档。

### 4.3 标准 3 — 护栏全绿：通过

500 局平衡自对弈、种子 10000、回合上限 30：

- 流局率 **9.60%** / 先手胜率 **50.40%** / 后手胜率 49.60%（成对报告，陷阱 C）
- 归元率 **90.40%** ∈ [75%, 95%]
- 先手胜率 **50.40%** ∈ [45%, 55%]
- 堆内存增量在 < 15MB 带内（运行期诊断，带噪声；本次确认运行约 -0.58MB）

生产基线归元率约 88.4%；候选把它抬到 90.40%，距上界 95% 只剩 4.6pp —— 这是落地后按
spec 决策 #13 重设护栏带时的新锚点。

`动态切换(调优v3)` 对 7 个静态预设，M = 2000/座次（每格 4000 局），双种子：

| 静态预设 | 种子 10000 胜率 (95% CI 下界) | 种子 20000 胜率 (95% CI 下界) |
| --- | --- | --- |
| 平衡 | 53.73% (52.18%) | 52.63% (51.08%) |
| 归元冲刺 | 74.17% (72.63%) | 74.55% (73.00%) |
| 激进压制 | 53.80% (52.25%) | 54.15% (52.60%) |
| 保守自保 | 69.33% (67.78%) | 66.85% (65.30%) |
| 纯推进 | 71.45% (69.90%) | 72.70% (71.15%) |
| 纯压制 | 94.53% (92.98%) | 94.70% (93.15%) |

### 4.5 改动前后逐格翻转

相对生产基线，种子 10000 翻转 **4 格**、种子 20000 翻转 **6 格**（种子 20000 额外翻转
归元冲刺/保守自保这一对，该对在种子 10000 为 within-noise）。核心翻转：

| A | B | 基线胜率 | 基线关系 | 候选胜率 | 候选关系 | Δ |
| --- | --- | ---: | --- | ---: | --- | ---: |
| 平衡 | 激进压制 | 42.20% | 弱 (A 负) | 52.45% | 强 (A 胜) | +10.25% |
| 激进压制 | 平衡 | 57.80% | 强 (A 胜) | 47.55% | 弱 (A 负) | −10.25% |
| 纯压制 | 剥离计分 | 56.80% | 强 (A 胜) | 37.70% | 弱 (A 负) | −19.10% |
| 剥离计分 | 纯压制 | 43.20% | 弱 (A 负) | 62.30% | 强 (A 胜) | +19.10% |

生产下「激进压制 6/6 严格占优」；候选下它输给平衡，「平衡 vs 激进压制」翻到 52.45%*，
「剥离计分 vs 平衡」为 55.67%*（压制计分被关掉的策略反而赢平衡 —— 相对价值翻转的直接证据）。

> **口径说明。** 上表是**采纳时**（相对采纳前的生产基线，即无 `ATTACK_PROGRESS_SCALE`）的对照，
> 数据保留自工单 06 的采纳运行。工单 06 已把进度定价写进生产 `POINTS_CONFIG`，因此现在再跑
> `--candidate progress-pricing` 时，工具默认的基线（`production`）与候选逐旋钮一致，
> 第 5 节「改动前后逐格对照」为空（复用候选矩阵，0 翻转）——那是预期的，不是证据丢失。
> 完整的采纳时逐格对照（42 个有序对）见工单 06 提交历史中的报告归档。

## 5. 默认动态策略 vs 调优动态策略：实现不足，不是设计意图不成立

候选 A 下 `DEFAULT_DYNAMIC_POLICY`（推进模式 = 归元冲刺权重、`advanceSelfMax = 2`）对平衡只有
0.485–0.51，落在噪声内，标准 4 失败。按 spec 决策 #12 必须区分：

- **翻转变量存在清晰过零**：标准 2 普查显示压制价值沿 `oppGuiYiNodes` 单调上升；
  C1 矩阵显示压制与推进互有胜负。相对价值确实随盘面翻转。
- **只改推进权重与切换阈值即可全胜**：把推进模式换成「激进骨架 + 建设项上调」、
  `advanceSelfMax` 2 → 7 后，同一规则下动态策略对全部 7 个静态显著全胜（§4.4）。

因此这是**该实现不足**，不是「设计意图不成立」。默认动态策略本身不改；调优策略作为
ticket 05 的检验工具（`TUNED_DYNAMIC_POLICY`），不进入生产默认。
