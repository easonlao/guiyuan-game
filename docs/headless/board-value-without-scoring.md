# 剥离计分后的盘面价值 (Board Value Without Scoring)

> Ticket 09。问题：激进压制对全部其它六个策略严格占优——这是**计分**造成的，还是**盘面节奏**造成的？
> 做法：用同一策略族、同一随机种子与样本量，在「计分轴关闭、AI 只按盘面判优」(`RuleSwitches.boardOnly`)
> 的条件下重跑跨策略对拼矩阵，与「计分轴开启」逐格对照。
> 结论：**盘面本身就足以让压制严格占优；单靠调计分无法修复。** 高流局率与压制型先手优势同样来自盘面，不是计分。

## 复跑命令

```sh
# 两个模式都跑，直接输出本文件的「逐格对照」报告
npm run benchmark:board-value -- --matches 2000 --seed 10000 --max-rounds 30

# 只跑 board-only 矩阵
npm run benchmark:board-only -- --matches 2000 --seed 10000 --max-rounds 30

# 只跑计分轴开启矩阵（现状）
npm run benchmark:head-to-head -- --matches 2000 --seed 10000 --max-rounds 30
```

- 样本量：每座次每格 2000 局；每个有序策略对合计 4000 局；7 个策略 → 42 个有序对 → 每个模式 84,000 局；两个模式合计 168,000 局。
- 种子基数：`10000`（第 i 局用 `10000 + i`，两个模式、两个座次使用完全相同的种子序列）。
- 回合上限：30 大回合；计分配置：生产默认 `POINTS_CONFIG`（两模式相同）。
- 座次平衡胜率 = (A 胜场 + 0.5 × 平局) / 两座次总局数；A 对 B 与 B 对 A 严格互补。

## 口径与实现说明

- **规则模式语义**：`board-only` 关闭的是 **AI 估值对规则得分的读取**（`ActionEvaluator` 中 `scoreDeltaPoints = 0`），
  不改动作合法性、状态转移或终局结算。回合上限结算仍按 `POINTS_CONFIG` 计分。
  因此本对照回答的是「AI 的压制偏好是否来自计分」，而不是「计分是否参与胜负」。
- **指标口径陷阱（本次修复）**：`HeadToHeadMatchup.drawRate` 原先把「平局率」(`winner === 'DRAW'`，本项目恒为 0)
  当成流局率输出，导致对拼报告的「流局率」恒为 0.00%。本次已改为 Metrics.ts 的唯一口径
  `drawRate = maxRoundsRate`（回合上限结算率），并另设 `trueDrawRate` 表示平局率。
  本报告所有流局率均为修复后的口径。修复前后 `seatBalancedWinRate` 不变（真实平局恒为 0）。
- **对照自检**：`纯推进`、`纯压制`、`剥离计分` 的 `scoreDeltaWeight` 均为 0，两模式下决策逐字节相同。
  因此它们两两之间的格子必须完全相同——报告里确实相同（例如 `纯推进 vs 纯压制` 流局率 64.65%、胜率 23.05% 两模式一致），
  证明模式开关确实只改变了 4 个读取计分的策略（平衡、归元冲刺、激进压制、保守自保）的决策。

## 结论

### 1. 激进压制的严格占优：盘面造成，不是计分造成

- **两个模式下 `激进压制` 都对全部其它六个策略严格占优。** 计分轴开启时它的胜率区间是 57.80%–80.85%；
  关闭计分轴后是 **79.53%–82.93%**——不仅没有消失，反而更均匀、更强（对 `平衡` 从 57.80% 升到 80.20%，
  对 `保守自保` 从 71.88% 升到 80.65%）。
- 对照自检：`纯推进`、`纯压制`、`剥离计分` 的 `scoreDeltaWeight` 本来就是 0，两模式下决策逐字节相同，
  它们两两之间的格子完全一致（如 `纯推进 vs 纯压制` 胜率 23.05%、流局率 64.65% 两模式一致）。
  因此两模式的差异**只**来自 4 个读取计分的策略（平衡、归元冲刺、激进压制、保守自保）。
- **裁定：盘面。** 关闭 AI 的计分读取后压制仍严格占优，说明「压制强」不是 AI 偏好计分的假象，
  而是压制动作在盘面与回合上限结算上的真实收益。计分只改变部分差距的**幅度**（尤其对 `平衡`），
  不改变**方向**。
- **因此：若盘面本身就让压制占优，单靠调计分无法修复。** 本次对照已明确满足这一条件——
  要修复必须动盘面/动作/回合上限结算，而不是只改 `PointsConfig`。

### 2. 高流局率来自盘面，不来自计分

- 全部无序对的平均流局率：scoring **37.19%** → board-only **44.65%**（不降反升）。
- 压制型对局在两种模式下都接近满流局：`激进压制 vs 纯压制` 99.33% → 99.72%；
  `纯压制 vs 平衡` 81.77% → 84.47%；`纯压制 vs 保守自保` 60.60% → 83.67%。
- 决策不受模式影响的格子流局率完全相同（见上表 `纯推进/纯压制/剥离计分` 之间的行）。
- **裁定：盘面节奏，不是计分。** 关闭计分读取后流局率普遍**升高**，说明高流局率是压制把对手拖入
  30 回合上限的盘面结果。

### 3. 压制型的先手优势来自盘面，不来自计分

- 全部无序对的平均先手(P1)胜率：scoring **54.15%** → board-only **56.25%**。
- 逐策略「先手胜率 − 后手胜率」（座次优势，按有序对平均）：

  | 策略 | scoring | board-only |
  | --- | ---: | ---: |
  | 平衡 | +7.97pp | +13.88pp |
  | 归元冲刺 | +3.47pp | +8.20pp |
  | 激进压制 | +13.59pp | +12.95pp |
  | 保守自保 | +4.68pp | +13.67pp |
  | 纯推进 | +4.82pp | +7.78pp |
  | 纯压制 | +14.41pp | +17.20pp |
  | 剥离计分 | +9.12pp | +13.88pp |

- 压制型（激进压制、纯压制）的座次优势在关闭计分后并未缩小（纯压制反而从 +14.41pp 升到 +17.20pp）。
- **裁定：盘面，不是计分。** 先手优势是盘面节奏（先手先展开/先压制）的产物，计分不是来源。

### 4. 一句话回答工单四问

1. 用同一策略族、同一 `seed=10000`、每座次 2000 局重跑完整对拼矩阵：完成（见上）。
2. 与现状逐格对照：**12 个有序格（6 个无序对）强弱关系翻转**，清单见「强弱关系翻转」。
   其中 2 个是统计临界格（`归元冲刺↔纯推进`、`平衡↔剥离计分`），其余 4 对为明显翻转。
3. 激进压制的严格占优：**盘面造成**；计分只影响幅度，不影响方向。
4. 高流局率与压制型先手优势：**都不来自计分**，来自盘面；关闭计分后两者都更大。
5. 盘面本身就让压制占优：**是**。因此单靠调计分无法修复。

## 发现的口径缺陷（本次已修复）

Ticket 06 的 `HeadToHeadMatchup.drawRate` 把「平局率」（`winner === 'DRAW'`，本项目恒为 0）当作流局率输出，
与 `Metrics.ts` 的唯一口径（`drawRate` 别名 `maxRoundsRate`，回合上限结算率）冲突，导致对拼报告的
「流局率」恒显示 0.00%。本票已修复：`drawRate` 改回流局率，另设 `trueDrawRate` 表示平局率；
`seatBalancedWinRate` 公式（胜场 + 0.5 × 平局）数值不变，因为真实平局恒为 0。
回归测试锁定：`对拼矩阵的 drawRate 是流局率（= 1 - 归元率），不是平局率`。

## 解释边界

- `board-only` 只关闭 **AI 对规则得分的读取**；回合上限结算仍使用生产 `POINTS_CONFIG`。
  因此本报告不能回答「若终局也改成纯盘面判定会怎样」。后者属于规则改动，超出本 spec 范围。
- 本报告是**测量**，不是改动建议。是否调整盘面/动作/结算，由 ticket 10/11 决定。
