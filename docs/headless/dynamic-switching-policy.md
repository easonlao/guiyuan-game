# 按盘面动态切换推进/压制 (Dynamic Switching Policy)

> Ticket 10 / spec `balance-audit-and-dominance`。本文是**实验**记录，不是规则改动建议。
> spec 第 19 条明确把**生产用**动态切换规则放在范围之外；本文只回答「按盘面在推进与压制之间切换」
> 这一设计意图能否在既有规则下打赢全部固定权重预设。
> 指标口径的唯一来源是 `src/core/headless/Metrics.ts` 与 `docs/headless/metric-definitions.md`；
> 本实验**未新增任何指标定义**，也未新增第三处接缝。

## 0. 复跑命令

```sh
# 主报告：主动态策略 + 5 个对照策略 × 7 个静态预设，每座次 2000 局
npm run benchmark:dynamic-switching -- --matches 2000 --seed 10000

# 只看主策略（更快）
npm run benchmark:dynamic-switching -- --matches 2000 --seed 10000 --no-sweep

# 稳健性：3 个种子基数 × 每座次 5000 局（结论的置信区间来自这里）
npm run benchmark:dynamic-switching -- --matches 5000 --seed 10000 --no-sweep
npm run benchmark:dynamic-switching -- --matches 5000 --seed 20000 --no-sweep
npm run benchmark:dynamic-switching -- --matches 5000 --seed 30000 --no-sweep

# 盘面模式（关闭 AI 对计分的读取）交叉验证
npm run benchmark:dynamic-switching -- --mode board-only --matches 2000 --seed 10000
```

命令由 `package.json` 长期保留，入口是 `src/core/headless/DynamicSwitching.ts`（确定性）。

## 1. 方法

### 1.1 为什么必须测动态策略

Ticket 09 已证明：**盘面本身**就让激进压制对全部其它固定预设严格占优（board-only 79.53%–82.93%），
计分只放大差距幅度、不改变方向。但现有六个预设**全部是固定权重**——用它们检验「根据盘面动态调整」
这一设计意图不对等。本实验补上动态一侧：一个逐回合按盘面在推进与压制之间切换的 `DecisionStrategy`。

### 1.2 切换依据（来自 ticket 08/09 的实测变量）

动态策略在每个决策点读取两个**已由 ticket 07/08/09 定义并锁过口径**的盘面变量：

| 变量 | 口径来源 | 含义 |
| --- | --- | --- |
| `countActionsToGuiYuan(board)` | `Metrics.ts`（ticket 07/08/09 使用） | 己方/对手「还差几次行动到五行归元」= 未点亮侧数 + 道损数 |
| 本回合最佳【破】的盘面边际收益 | `Metrics.atkTempoGain`（ticket 08） | 目标侧 0/1 → +1；加持 2 → 0；无合法【破】→ 无值 |

**切换规则（主策略 `动态切换`）：**

```
默认压制。
推进，当且仅当满足其一：
  (a) 赛跑领先：selfActionsToGuiYuan <= 2 且 lead = oppActionsToGuiYuan - selfActionsToGuiYuan >= 1；
  (b) 破节奏拐点：本回合最佳合法【破】的盘面收益 == 0（只能打加持 2 的侧）。
```

**为什么选它：**

1. **默认压制**是 ticket 09 的直接推论——盘面让压制占优，举证责任在「推进」一侧。
2. **条件 (b) 直接落在 ticket 08 的软拐点上。** ticket 08 结论：一次【破】的盘面收益是逐侧阶跃函数，
   打加持 2 的侧收益为 0（加持吸收了打击），而 0→-1、1→0 都是 +1；硬封顶（对手全道损）在真实对局中
   几乎不出现（见 §4 分布）。因此「本回合打不出盘面收益」是唯一被 ticket 08 实测支持的「该改推进」信号。
3. **条件 (a) 对应设计意图的「我更快归一」。** 己方还差 2 次行动且领先时，推进应该能收掉比赛。
4. 两个子策略分别是既有的一等预设：推进 = `RUSH_GUIYUAN_WEIGHTS`（归元冲刺），
   压制 = `AGGRESSIVE_WEIGHTS`（激进压制）。两者用同一份计分配置与规则开关构造，切换只改权重、
   不改估值口径，从而隔离出「切换」本身的贡献。

### 1.3 座次平衡与接缝

- 每个「动态策略 × 静态预设」对调用一次 ticket 06 的 `runHeadToHeadMatrix`：同一对打两个座次
  （A 执先手 / A 执后手），使用同一随机种子序列；座次平衡胜率 = (胜场 + 0.5 × 平局) / 两座次总局数，
  因此 A 对 B 与 B 对 A 严格互补。
- 策略通过既有主接缝 `HeadlessMatch.run` 注入；对局批量由 `runHeadToHeadMatrix` → `HeadlessBenchmark.run`
  发起。统计采集单独用 `HeadlessMatch.run` 逐局循环（同一批种子），每局开始重置「上一次模式」，
  使「切换次数」按局内连续决策统计。
- 动态策略是标准 `DecisionStrategy`；`StrategyVariant` 新增可选 `create` 工厂以容纳「单一权重模板
  无法表达」的策略，既有预设缺省走原路径、行为不变。

### 2.3 稳健性：这一优势有多大、有多稳？

单格 4000 局的胜率标准误约 0.79 个百分点，因此 2000/座次下单看「50.68% vs 激进压制」与 50% 无法区分。
把 3 个互不重叠的种子基数 × 每座次 5000 局（每个 matchup 合计 30,000 局，标准误约 0.29 个百分点）合起来看：

| 动态策略 | 种子 10000 | 种子 20000 | 种子 30000 | 合并 | 95% 置信区间 |
| --- | ---: | ---: | ---: | ---: | --- |
| 动态切换 vs 激进压制 | 50.49% | 50.84% | 50.80% | **50.71%** | [50.14%, 51.28%] |
| 动态切换 vs 平衡 | 56.39% | 56.97% | 57.56% | 56.97% | [56.40%, 57.54%] |
| 动态切换(仅破节奏) vs 激进压制 | 50.71% | 50.97% | 51.04% | **50.91%** | [50.34%, 51.48%] |
| 动态切换(仅赛跑) vs 激进压制 | 49.76% | 49.97% | 49.97% | 49.90% | [49.33%, 50.47%] |
| 对照(从不切换) vs 激进压制 | 50.00% | 50.00% | 50.00% | 50.00% | —（恒等） |

**结论：在计分轴开启时，动态策略确实打赢全部静态预设，但对最强预设（激进压制）只赢 0.7 个百分点，
置信区间刚刚越过 50%；对其它预设赢 4–31 个百分点。**「从不切换」对照恒为 50.00%（它与激进压制逐字节相同），
所以切换本身的净收益约 +0.7pp。

## 3. 过程中的实际切换频率与依据分布（主策略）

统计覆盖主策略 vs 全部 7 个静态预设、两个座次，共 28,000 局、946,502 次动态决策。

| 指标 | 数值 |
| --- | ---: |
| 推进决策 | 58,001 (6.13%) |
| 压制决策 | 888,501 (93.87%) |
| 模式切换次数 | 58,351（平均每局 2.08 次） |
| 依据 `close-to-guiyuan` | 36,987 (3.91%) |
| 依据 `suppression-has-no-board-tempo` | 21,014 (2.22%) |
| 依据 `suppress-default` | 888,501 (93.87%) |

**切换依据的分布（决策时点的盘面变量）：**

| 变量 | 分布 |
| --- | --- |
| 本回合最佳【破】盘面收益 | `1` 445,394 (47.06%) / `0` 25,326 (2.68%) / 无合法【破】 475,782 (50.27%) |
| 己方还差行动 | 1:2.97% / 2:9.27% / 3:16.77% / 4:19.65% / 5:16.86% / 6:12.95% / 7:8.88% / 8:5.74% / 9:3.84% / 10:3.07% |
| 对手还差行动 | 1:4.38% / 2:13.40% / 3:18.92% / 4:18.76% / 5:15.98% / 6:11.59% / 7:7.43% / 8:4.67% / 9:3.36% / 10:1.51% / 11:0.00% / 12:0.00% |
| 赛跑领先量 (对手−己方) | −5..−3 ≈0.3% / −2:3.65% / −1:41.07% / 0:46.56% / +1:6.58% / +2:1.45% / +3..+6 ≈0.4% |

三条关键观察：

1. **实际切换频率很低**：只有 6.13% 的决策走推进，平均每局 2.08 次模式切换。
2. **硬封顶几乎不出现**：对手还差行动从未超过 12，绝大多数落在 2–6；ticket 08 的「全道损 = 20」硬封顶
   在真实对局中不构成信号。真正可用的 ticket-08 信号只有「打加持 2 收益 0」这一软拐点。
3. **赛跑领先很少**：领先量 87.6% 落在 −1/0；「己方快且领先」条件 (a) 只在 3.91% 的决策触发，
   且 §2.3 显示「仅赛跑」变体反而低于 50%。

## 4. 哪一半信号真正有用？对照策略拆解

| 动态策略 | 推进条件 | 计分模式 vs 激进压制 | 盘面模式 vs 激进压制 | 判定 |
| --- | --- | ---: | ---: | --- |
| 动态切换 | 赛跑 + 破拐点 | 50.68%（30k 合并 50.71%） | 49.90% | 勉强全胜 |
| 仅破节奏 | 破拐点 | **51.05%（30k 合并 50.91%）** | **50.05%** | 最强，两种模式都全胜 |
| 仅赛跑 | 赛跑 | 49.75% | 49.85% | 输 |
| 对手未建设 | 对手还差行动 ≥ 8 | 49.85% | 50.42% | 临界 |
| 纯推进/纯压制 | 赛跑 + 破拐点 | 19.48% | 20.85% | 子策略换成极端后大幅变差 |
| 对照(从不切换) | 从不 | 50.00% | 50.00% | 退化基准 |

- **有用的信号是 ticket 08 的软拐点（打加持侧收益 0）**，不是赛跑。去掉赛跑条件后，主策略在两种模式下
  都稳定 > 50%；只保留赛跑条件则 < 50%。
- **赛跑条件是冗余甚至有害的**：`winReward` 已经让压制子策略（激进压制）在能立即归元时选择归元动作；
  额外的「快归元就推进」只在**不能立即赢**的盘面上生效，而那些盘面恰恰是压制更优的地方。
- **「纯推进/纯压制」变体崩溃**（19.48%）说明：切换机制本身没问题，但把子策略换成关闭计分轴的极端预设后，
  推进一侧太弱，切换无法弥补。

## 5. 盘面模式（计分轴关闭）交叉验证

| 动态策略 \ 静态预设 | 平衡 | 归元冲刺 | 激进压制 | 保守自保 | 纯推进 | 纯压制 | 剥离计分 | 全胜? |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 动态切换 | 77.98% | 81.38% | 49.90% | 79.35% | 78.45% | 79.57% | 77.98% | 否 |
| 动态切换(仅破节奏) | 79.60% | 83.33% | 50.05% | 80.47% | 81.00% | 79.57% | 79.60% | 是 |
| 对照(从不切换) | 80.20% | 82.93% | 50.00% | 80.65% | 80.45% | 79.53% | 80.20% | 否 |

盘面模式下主策略对激进压制 49.90%（未过 50%），只有「仅破节奏」变体勉强全胜（50.05%）。
这与 ticket 09 一致：**关闭计分后压制优势更强，动态策略的可用空间更窄。** 计分模式下那 +0.7pp 的净收益，
一部分来自「放弃打加持侧的 WEAKEN 分、换取盘面节奏」的交换；关掉计分后这个交换的价值改变，
主策略的赛跑条件又把这点收益抵消掉了。

## 6. 结论：动态策略能否打赢全部静态预设？

**能，但只是勉强、且只在计分轴开启的生产模式下。**

1. **能否全胜？** 计分模式：**能**——7 格全部 > 50%。盘面模式：主策略**不能**（49.90%）。
2. **赢多少？** 对最强预设激进压制 **+0.71pp**（30k 局合并，95% CI [50.14%, 51.28%]）；
   对次强的平衡 **+6.97pp**；对其余预设 **+19.75–31.25pp**。单看 2000/座次时对激进压制的差距与 0 无法区分。
3. **赢在哪里？** 全部净收益来自 **ticket 08 的软拐点**：当本回合只能打加持 2 的侧（盘面收益 0）时，
   动态策略改走推进，不再打这一记空枪。去掉这个条件（仅赛跑）就输；只留这个条件（仅破节奏）反而更稳。
4. **设计意图是否成立？** **只弱成立。** 设计意图的两个半边里，「阻碍对手」被证实是主导轴（与 ticket 09 一致），
   而「我更快归一就切换」这一半边**没有独立价值**——能立即归元时激进压制预设自己就会归元，
   不能立即归元时推进只会让出盘面优势。可用信号窄到只剩「打加持侧是空枪」这一条。
5. **是设计意图不成立，还是本实现不足？** 证据偏向 **(a) 设计意图在当前规则下基本不成立**，
   理由是：对照策略「从不切换」恒为 50%，而所有真正切换的变体都只是在这一基准上下 0.7pp 内浮动；
   盘面模式下降至 49.90%。搜索并非穷尽，因此不能完全排除 (b)，但**可改进方向的收益空间已被压缩到 1pp 量级**。

### 若判为「实现不足」，可尝试的改进方向（均超出本 spec 范围）

- **换切换信号**：本实验只用了「赛跑领先」与「破收益为 0」。可尝试的替代信号包括
  对手残留道损的**增量**（而非绝对值）、己方归一节点数、回合阶段（早期压制 / 残局推进），
  但 §3 的分布显示这些变量在真实对局中变化范围很小（对手还差行动 2–6、领先量 −1/0）。
- **换子策略**：把「推进」子策略从归元冲刺换成更强的建设策略，或做逐动作的连续权重插值，
  而不是在两套固定权重间硬切。
- **改规则而非改 AI**（真正的杠杆）：ticket 08 已指出，盘面让压制无递减、提前压制不亏是失衡的必要前置。
  要让「切换」有空间，需要让压制在某个可达盘面区域出现**真实的边际递减或代价**
  （例如恢复/强化「打加持侧空枪」的代价，或给持续压制加反噬），这不是 AI 侧能解决的。

## 7. 口径与解释边界

- **未新增指标、未新增接缝。** 切换依据只读 `Metrics.countActionsToGuiYuan` 与 ticket 08 的 `atkTempoGain`
  口径（本模块的 `bestAvailableAtkTempoGain` 是该口径的盘面查表：目标侧 0/1 → 1，2 → 0，无合法目标 → 无值）。
- **座次平衡**：每个 matchup 打两个座次、同一批种子；胜率 = (胜场 + 0.5 × 平局) / 总局数，A/B 严格互补。
- **`board-only` 语义**：只关闭 AI 对规则得分的读取，不改动作合法性、状态转移或终局结算。
- **本实验不回答**「生产环境是否应采用某条动态规则」；spec 第 19 条已把生产切换规则置于范围之外。
- **统计显著性**：单座次 2000 局的标准误约 0.79pp，5000 局约 0.50pp，30,000 局约 0.29pp；
  对激进压制的 0.7pp 优势只有在大样本合并后才越过 50%，不应据单次 2000 局下强结论。

## 8. 复跑自检

`tests/core/dynamic-switching.test.ts` 锁定行为（不复述报告数字）：

- 切换依据：破收益为 1 时压制、为 0（加持）时推进、赛跑领先时推进，且赛跑条件可分离；
- 切换确实改变对局轨迹（同一批种子下与固定激进压制预设的记录不同）；
- 逐决策统计的计数自洽（推进 + 压制 = 决策数、依据计数之和 = 决策数），且跨局首决策不误记为切换；
- 对拼矩阵覆盖全部 7 个静态预设、每对两个座次、胜率互补，同一输入确定性复现。
