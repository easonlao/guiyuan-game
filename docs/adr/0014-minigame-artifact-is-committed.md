# 小游戏产物 `minigame/game.js` 入库，用逐字节对账门禁盯漂移

`src/minigame/` 经 Vite 打成单文件 IIFE `minigame/game.js`，产物**提交入库**；一道独立门禁（`npm run check:artifact`，已串进 `npm run verify`）重跑同一条构建命令、与入库产物**逐字节比对**，不一致即红。产物落点写死「不得落在任何 `dist/` 下」。产物保持不压缩，入库的那份在 diff 里可读。

## 背景与问题

真机验收步骤（现归 `docs/HLD.md` §4.6）让人打开微信开发者工具、**直接导入 `minigame/` 目录**。如果产物不入库，每次导入前都得先跑一次构建。

决定是「入库」，但**理由只有一条，而且比它看起来弱**：省下的是一次命令。这不是「产物是某种对外契约」那种强理由——见下面的被否决方案。

## 决定

1. **产物入库**：`minigame/game.js` 提交进版本库。
2. **加对账门禁**：`npm run check:artifact` 用与 `build:minigame` **同一次**构建调用现打一份，与入库产物逐字节比，不一致即红；已串进 `npm run verify`（验收档）。
3. **落点写死**：产物不得落在任何层级的 `dist/` 下，这条判定写在门禁脚本里，不靠 `.gitignore`。
4. **产物不压缩**：`minify: false`。入库的那份要能在 diff 里读，这是「入库」这个决定能被人复核的前提。

## 被否决的方案

- **不借参考仓库的第三方契约类比（关键）**：参考仓库 model-war 的 `runtime.iife.js` 入库，是因为那串字节是**第三方契约**——sha256 写进回放 meta，别人靠它复算历史对局（它的 ADR-0007）。`game.js` 是微信小游戏的 UI 包，**没有任何第三方依赖它的确切字节**。两条决定不是同一类：那边「确切字节」本身就是判据，这边只是为了省一次构建命令。借那个类比会把一条弱理由包装成强理由，所以本 ADR 明确不引它作依据。
- **不入库、每次导入前构建**：落选——`docs/DEVELOPMENT.md` 的验收步骤是给人（需求方）走的，多一步命令就多一处卡壳。省下的确实只是一次命令，但省在这里值。
- **入库但压缩产物**：落选——压缩后的产物在 diff 里读不出改了什么，复核入库产物的成本高于省下的命令。
- **只靠 `.gitignore` 兜落点**：落选——`.gitignore` 的 `dist/` 是**无锚点**规则，命中任意层级；产物一旦落进任意 `dist/`，它会静默不进库，「入库」当场成空话，而且没有任何门禁会红。落点判定必须在门禁里写死。

## 后果

- **产物与源码可以分叉，因此必须有一道门禁盯着**：改源码不重跑构建，库里的产物就停在旧版，而它照样能被微信开发者工具载入——不盯着就是「工具里看到的还是旧的」。`check:artifact` 的逐字节比对把这条堵死，红的时候指得出第一个不同的字节位置。
- **落点不得在任何 `dist/` 下**：`.gitignore` 的无锚点 `dist/` 是已知的坑（参考仓库 ADR-0007 专门记过）；本仓库的落点是 `minigame/game.js`，与 `src/minigame/` 同族但不同层，由门禁第一条判定钉住。
- **门禁与 `check:boundary` 是两条不同的门**：`check:boundary` 管「包边界机制还成立吗」（声明式解析），`check:artifact` 管「入库产物 == 现打产物」。判定对象不同，不合并。
- **构建面必须只有一处**：写回侧（`build:minigame`）与核查侧（`check:artifact`）共用 `scripts/lib/minigame-build.mjs` 的同一次构建调用。各写一份 vite 配置，两者就可能悄悄用上两条不同的构建命令——那正是分叉的入口。
