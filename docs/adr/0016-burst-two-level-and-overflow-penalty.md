# 恢复爆发双级作用与满溢则亏，并放开爆发生成门槛

重构为纯 TS 核心时，爆发动作的两级作用退化成了单级：按钮文案写着「消耗木·生火 **+2**」「消耗木·克土 **-2**」，代码与 GDD 却只作用一级。本 ADR 记录「恢复两级、让满溢与亢极一致、并放开门槛」的决策与理由；规则正文（真值表、门槛条件）归 `docs/GDD.md` §2.3，载荷契约归 `docs/LLD.md` §3.1，本文不复述。

## 背景与问题

同一个事实在四个地方有三个版本（本决策落地前的状态）：

- **旧实现 `+2`**：重构前的 JS 实现（`ca2bdde:legacy/src/logic/actions/ActionResolver.js` 的 `applyBurst` / `applyBurstAtk`）显式连做两次 `±1`，每次重新选侧；归档的规则基线报告（`docs/archive/headless-rule-baseline.md`，证据不是定义）记录的结算结果同样是双级。
- **UI 文案 `+2`**：按钮副标题写「消耗木·生火 **+2**」「消耗木·克土 **-2**」（`src/minigame/action-button-formatter.ts`），至今未变。
- **GDD `+1`**：重构后的 §2.3 写「使其对应侧 `+1`」。
- **代码 `+1`**：重构后的 `ActionResolver` 只做一次 `±1`。

也就是说，按钮文案从一开始就是对的，是重构把实现与 GDD 一起改错。

第二个问题由亢极设定引出：原设计里相生节点满盘 `(2,2)` 时第二次强化是空操作（溢出的那一级直接丢失），但 GDD 已有「满溢则亏」的亢极散气——满盘节点再受滋养却毫无代价，与亢极的直观相反。

## 决定

1. **恢复两级、逐次施加。** 强化与强破都改回两次独立的 `±1`；每次施加前重新读盘面、按**阴侧优先**重新选侧。不做「同一侧 `±2`」的合并，也不做一次性的整体平移。
2. **满溢则亏。** 强化某一次 `+1` 面对亢极 `(2,2)` 时，该次改为对**阴侧 `-1`**，计 0 分，与亢极散气的结果一致；选侧仍按阴优先，不跟随抽中天干的极性。
3. **强破见底即止。** 强破的两次 `-1` 在两侧都到道损 `-1` 时停止，不反转、不溢出——底部没有与亢极对称的机制。
4. **放开生成门槛。** 目标已达极值不再封死爆发：相生目标 `(2,2)` 时强化仍可选，相克目标 `(-1,-1)` 时强破仍可选。盘面净零，但照样换取一次连动与动作分。化与吸纳的门槛不动——它们不换连动，放开只会多出空转按钮。
5. **契约：爆发候选不再携带预先钉死的目标侧。** 作用侧既然在解析时逐次决定，载荷里预钉的那个值就失去意义；`polarity` 字段本身不动，其余动作的候选形状也不变。契约正文归 `docs/LLD.md` §3.1。

## 被否决的方案

1. **纯 clamp：溢出的那一级直接丢弃**（维持「`(2,2)` 再强化是空操作」）。否决原因：同一盘面上与亢极散气给出相反直觉——满盘节点被滋养反而毫无代价，玩家无从预期。
2. **两级同步施加：「阴 `+1` 再阳 `+1`」**（或反向的固定顺序）。否决原因：它不重读盘面，`(1,0)` 这类盘面会被抬成 `(2,0)` 而不是 `(2,1)`；「阴阳各一次」也不是「阴优先」的语义——阴优先是逐次重判，不是交替。
3. **维持门槛关闭：目标已达极值时不给爆发。** 否决原因：封死会把连动出口从「源节点已归一 + 目标极值」这一整类盘面里拿掉，玩家只剩与局面无关的常规动作甚至无动作可做。

## 后果

- **爆发在亢极附近退化为廉价的节奏/刷分动作**：净零或近净零的盘面变化，仍换一次连动与动作分。这是被接受的代价；真实收益结构（含最低档分、源节点因消耗失去归一的拖慢）应在平衡基准里被观测，而不是被假设。
- **平衡护栏必须重跑，不能沿用旧结论**：这次改动重新抬高了爆发的收益，ADR 0002 关于爆发刷分的结论只对旧幅度成立。实测数字与在带内/带外的结论见工单 03 的对账与基准记录（`.scratch/archive/burst-plus-two/issues/03-evaluator-reconciliation-and-balance-guardrails.md` 的 Comments，或其在 `docs/headless/` 下落盘的报告）；本文不复述数字。
- **规则正文与契约各归其位**：GDD §2.3 已随实现回写，§2.4 的唯一候选枚举随之修订；载荷契约在 LLD §3.1。
