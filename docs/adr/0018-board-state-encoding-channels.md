# 法盘状态编码：五行色表身份、等级走亮度阶梯、节点级状态与候选标记各占独立通道

## 背景与问题

表现层的等级原来由色相承载——工单 08 定的规则是「1 五行色、2 同一五行色发光」，虚空 (0) 与道损 (-1) 都用暗底。新一轮画面复查暴露三处误读：盘下图例的四个等级样例**全部用木色画**（`src/minigame/game-scene.ts:858-862` 把 `WuXing.WOOD` 写死传入），玩家于是把「绿」读成「点亮」；虚空与道损同为暗底（`src/minigame/views/board-view.ts:536`），在对方环约 20px 半径的半鱼上分不出来；归一与亢极在盘上没有任何标记——`isGuiYi` 只被拿去数「你 x/5」（`board-view.ts:488`），`isKangJi` 投影出来后无人读（`board-view.ts:287`、`:361`）。根因是同一根色相通道被身份与等级同时征用。

## 决定

把标记分成三层，每层占一条互不重叠的通道。

1. **每一侧（鱼半身）**：色相恒表**五行身份**，任何等级都保留自己的五行色；等级只走**亮度阶梯**——虚空 = 空心（只留五行色淡描边）、点亮 = 五行色实心、加持 = 实心 + 光晕、道损 = 暗化的五行色 + 裂纹。
2. **节点（主印外侧）**：归一 = 一圈金环；亢极 = 双层金环。中性表达「多一层就是更满」，不用警示色、不用脉动。
3. **候选与预览（半环外沿）**：会变的那一侧外侧挂一段五行色弧；决策期**同相位慢呼吸**（所有候选共用一个节拍），按住按钮时该弧加快，并叠加路径箭头（化 = 内环顺时针弧箭、破 = 径向箭）与目标侧的下一步幽灵态。

同时拍死三处取舍：**虚空用空心而不是暗底**（空心与实心在约 12px 宽的半鱼上仍然可分，两个暗底不能）；**决策期不做逐节点闪动**（归一局面最多 3 个候选、2 个不同落点，各自闪就是工单 08 想消除的信息混杂）；**对方盘不再整体变暗**（在新通道里「暗」已经等于虚空，再调暗对手会让它的虚空与点亮分不出来，归属改由环带的实线/虚线加「你 / 天道」标签承担）。

## 被否决的方案

- **维持工单 08 的「色相 = 等级」，只把图例改成「以木为例」**：治不了根。只要「有没有色」等于「点不点亮」，玩家就得先解码颜色才知道状态，换到火 / 土 / 金 / 水节点时图例与盘面依然对不上。
- **给每一侧常驻小点数或数字**：读数最准，但在对方环约 12px 宽的半鱼上挤成一团，反而增加噪声。改为按住预览时才显示准确读数。
- **亢极用警示色或脉动**：亢极确实会强制散气，但它同时满足归一门槛、也是强化的合法源，染红会让玩家把最高进度读成坏状态。**未采纳**，改用「金环多一层」。
- **保持对方盘整体变暗以区分主次**：归属其实已由环带的实线/虚线与「你 / 天道」标签说清，主印大小不必再兼这一份差事；而变暗会直接撞坏新的等级通道。**未采纳**。

## 后果

- 工单 08 的「1 五行色、2 同一五行色发光」作废；盘下图例与上一招变化条的文案统一到 `GLOSSARY.md` 正名「道损 / 虚空 / 点亮 / 加持」（`崩坏`、`发光` 已列入该表的 _Avoid_）。
- 撤掉对方盘的整体暗化后，外环主印需要放大到接近内环；`BoardView.resize` 的主印不重叠保证（`board-view.ts:187`）要一并把归一环的外扩算进去。像素取值归 `docs/HLD.md` §2 Layer 3 与代码常量，本 ADR 只记编码约定。
- 候选弧与路径箭头不需要新管道：`resolveActionPath` / `setActivePaths` / `BoardConnectionView.isActive` 都还在，只是 `renderSelf` 不再画它们（`board-view.ts:367-372`）。但**强化与强破的目标侧不在载荷里**（解析时逐次重读盘面、各自按阴侧优先决定），它们的预览必须真跑一遍解析器，不能沿用现有兜底的近似落点。
- 图例只剩「亮度 ↔ 等级」一件事要教：五个节点在任何等级都带自己的五行色描边，图例不必再教「颜色 ↔ 元素」。

## 勘误：节点级标记改为「环 + 流动 + 元素外溢」（票 02 落地时追加）

本节只记录现状，不改变上文的分层结构；但「亢极 = 双层金环」与对「脉动」的一刀切已被取代。

- **归一 = 一圈金环 + 沿环缓慢流动的金色高光**（4.5s 一圈、长尾渐隐）：只要节点归一就有，与是否亢极无关。
- **亢极 = 归一那一层之上再叠五行色柔光**（取该节点的五行色）+ **一圈外扩涟漪**（比归一更慢更淡）——表达「满溢 / 泄露 / 不稳」。
- 因此上文「决定 2」的「亢极 = 双层金环」「多一层就是更满」作废；「不用脉动」放宽为**不用警示色**：节点级状态现在带运动（金色流动 / 五行色涟漪），但归一用中性金、亢极用节点五行色，均不借用警示色相。当初拒绝脉动是为了不把亢极读成坏状态，这条理由仍成立，故只允许「流动 / 满溢」的运动语义，不允许闪烁或警示色。
- 像素取值（环半径、线宽、流光周期与拖尾、外溢尺度、涟漪周期）以 `src/minigame/views/board-view.ts` 常量为真源；法盘底晕按 `NODE_AURA_OUTSET_RATIO` 放大以容纳五行色外溢，票 05 的 `resize` 避让改用同一个常量（不再是环间距）。

## 勘误：候选标记从「外侧挂弧」改为「半身染色闪烁」（票 03 落地时追加，含数轮用户改口）

「决定 3」的候选通道已落地，但**标记形态与配色被用户连续改口**：本节只记录现状，不改变分层结构。

- **决定 3 原措辞作废**：「会变的那一侧外侧挂一段五行色弧」不再采用。实测反馈：额外画一个「弧 / 括号」是要先解码的符号，玩家不一定能把它读成「这一侧能打」；而且弧与归一金环同轴同区，区分成本高。
- **改为「直接染会变的那半身」**：把该极性的鱼形（阴鱼 / 阳鱼）用强调色染色（正常混合、由内向外加深）+ 一条薄轮廓勾形，随共享节拍呼吸。好处：「左鱼在闪 / 右鱼在闪」直接对应按钮上的「(阴)」「(阳)」，不需要额外解码。
- **标记用专属强调色，不取五行色**（追加一次）：先用**五行色加亮**做过一版，实测在亮底（点亮 / 加持）上会趋近白，与「加持」的径向光晕读成同一种东西（金最明显）；第一版换成紫时外圈误用了近白，半身被洗白，肉眼读不到紫。现在染色**两端都用紫**（`THEME.candidate` / `candidateDeep`，描边用 `candidateLit`；具体色号见下一段的定档），靠**色相**而不是明暗区分。这不违反「颜色只归身份」：强调色既不是任何五行色、也不是节点级状态的金，不可能被读成某种身份或某种状态；半身填充（身份）与亮度阶梯（等级）都不受影响（染色保留约一半透明度，等级仍透得出来）。
- **不做粗边框**（追加一次）：为救上面那版「淡白对比度」加过「外暗内亮双色粗边」，颜色改成饱和紫后色相自己就能读，那圈粗边只剩副作用（读成一条不自然的大粗边），已撤掉，只留一条与半身自身描边同档的薄轮廓。
- **标记常亮、呼吸只调深浅**：低位不透明度不为 0，保证「紫 = 这里能打」在任何时刻都成立；呼吸同时调胀缩（`CANDIDATE_SWELL_*`）与染色深浅，位移不受底色影响。
- **「不做逐节点闪动」放宽为「不做逐节点各自闪动」**：候选之间仍然**同相位**（单标量相位，所有标记同时明暗），当初反对的是「各自闪造成的信噪混合」，同相位不构成这个问题。这条与票 02 勘误里「只允许流动 / 满溢」的关系：那条约束的是**节点级常驻状态**（要中性、不能被读成坏状态），候选标记是**决策期临时提示**，不在此限。
- **落点口径不变**：仍取「会变的那一侧」（`getActionTargetElement(action)` + 候选载荷的 `polarity`），**不从抽中天干的极性推导**——吸纳 / 调息 / 散气在源节点，化 / 破 / 爆发在目标节点。只有爆发两类的载荷不带 `polarity`（核心 `ActionResolver` 逐次阴优先决定作用侧），按同一套规则从盘面推出第一次会变的一侧，与核心层共用选侧真源。
- **PASS 与净零变化不画**：`PASS` 原地消散；强破打在双侧均已道损的目标上核心层「见底即止」，两者都无落点。
- **色号定档**（追加一次）：给过四个候选（当前紫 `#8b5cf6` / 内敛紫 `#8d76c9` / 玫红 `#d9569b` / 青绿 `#2ec4b6`）的并排对比图，用户选定**内敛紫** `#8d76c9`（配 `#6f5aa8` / `#cfc2ee`）——理由是与水墨 + 金的盘面更合，代价是亮底上色相距离更小（实测 B−R 约 36，鲜艳紫约 66）。否决的：玫红（与「火」同属暖红家族）、青绿（离「水」与对方环带青灰太近）。
- 像素取值（染色色号与透明度、轮廓线宽、呼吸周期与区间、胀缩比例）以 `src/minigame/views/board-view.ts` 与 `src/minigame/theme.ts` 常量为真源；鱼形几何与 `drawYinYangFish` 共用 `traceFishHalf` 这个单点真源。
- 路径箭头与按下时的加速留到票 04（按住预览）。

## 勘误：按住预览落地（票 04 追加）

「决定 3」的按住预览已落地；本节只记现状与落地时拍定的取舍，不改变分层结构。

- **触发与取消**：`ActionBarView` 把按钮的按下 / 抬起（含手指移出后抬起）转成 `onPreview(action | null)`，`GameScene` 据此驱动 `BoardView.setPreview`。为让「取消」成立，`InputManager.handleTouchEnd` 改为恒定把抬起回调发给**按下时命中的节点**（此前只发给抬起时命中的节点，手指移出后按钮会停在按下态、也无人清预览）。换阶段（`GameScene.setPhase`）一并清空预览。
- **路径箭头**：`isActive` 在按住时收窄到这一下的路径；相生（化 / 强化）画内环外侧一段顺时针弧 + 箭尖，相克（破 / 强破）画跨环径向直线 + 箭尖。墨用候选标记的专属强调色（紫），不是节点级状态的金色流光——箭头与半身标记属于同一层「决策期临时提示」。决策期不按住时不画任何箭头（与此前「盘面不画候选连线」一致）。
- **幽灵态**：目标侧真的会变的那几侧，先把该半身压暗（否则降级到虚空看不出变化），再半透明画结算后的等级形态。**真跑一遍 `ActionResolver`**（`src/minigame/preview-target.ts`）取目标节点结算后的等级：强化 / 强破的目标侧不在载荷里、各作用两次，只有解析结果才与结算逐侧一致；净零变化（如强化打相生 (2,2)）、`PASS`、强破见底即止都不画。未变的半身不动。
- **加速**：按住时所有候选的呼吸一起加快（`PREVIEW_BREATH_SPEED`）。票 03 勘误里「候选之间同相位」是硬约束，不能只加快被按住那一个——「是哪一下」由路径箭头与幽灵态指出，不靠相位分辨。
- 像素取值（箭头半径 / 线宽 / 箭头长、幽灵透明度与压暗量、加速倍率）以 `src/minigame/views/board-view.ts` 常量为真源；幽灵态的等级形态与半身共用 `drawYinYangFish`。

## 勘误：相克用贯穿突刺、调息用漩涡（票 04 视觉复核追加）

用户复核：「攻击的展示可以再考虑如何优化，用一个这么呆板的直线完全没有设计感」，「调息的含义就是内部流转转化」，「游戏规则简单，画面动画就要设计得出彩」。给出六个候选方案对照（`reports/ui-design/p04-options.png`）后，用户选定两排的 **B**。本节只记现状。

- **相克用贯穿突刺（B）**：一枚能量尖锥从本阵主印外沿刺向敌节点，尖端穿出敌印；两侧拉出速度线，落点处有向外扩的冲击波，尖端有能量头。不是直线，也不只是一条弧。
- **调息用漩涡（B）**：一股能量从当前点亮侧（大半径）螺旋一卷卷到对侧（小半径），拖一条渐隐的尾与能量头。调息不跳节点、`resolveActionPath` 对它返回 `null`；调息节点不可能归一，主印外没有金环占位，漩涡才放得下。
- **动画**：两条运动（突刺能量头 / 冲击波、漩涡流转）都挂在表现层时钟 `BoardView.tick(dt)` 上，与归一金环流光 / 亢极外溢共用同一条时钟，不另起。
- 像素取值仍以 `src/minigame/views/board-view.ts` 常量为真源；实现形态自查图 `reports/ui-design/p04-rev3.png`（本地证据，不入库）。

## 勘误：外环放大与环间距重算（票 05 落地时追加）

「决定 3」里「对方盘不再整体变暗」当时只说了去掉暗化、没说尺寸。本票把尺寸一并拍定，并处理由此牵出的避让口径。

- **归属完全交给环带与标签，尺寸差相应收窄**：对方盘主印缩到只比己方略小（约 0.92 倍），归属判断不再依赖「更大 / 更小」——此前 0.82 的差距加上「更暗」是一个整体信号，暗化撤掉后单靠尺寸差已经不足以一眼分出两块盘。缩放比与像素取值以 `src/minigame/views/board-view.ts` 常量为真源。
- **环间距按金环外沿预留，盘面外沿按元素外溢预留**（两者不是同一个口径）：金环是**实线**，压到相邻主印上就是硬伤，故同环相邻（按弦长 `2R·sin(π/5)`）与跨环都按金环外沿留间距；亢极元素外溢是**渐隐到 0 的柔光**，与相邻主印交叠只读成更亮的一层晕，交叠本身不算失败，若拿它约束环间距会把主印压到看不清——但盘外没有邻盘可交叠，故盘面上下外沿仍按满额预留，外溢与归元图例不越出内容边界。
- **主印半径有可读性下限**：避让装不下时按比例让位给避让，但不低于下限的一定比例——再小就不成其为法盘了，此时宁可让外溢稍稍越界。
- **五行标签径向避让**：五行文字标签统一改为内环向盘心收敛、外环向盘外发散的径向位置，避开外环金环与相邻主印，消除文字与主印/光效的遮挡。
- **操作栏恒定预留与跨回合布局恒定**：操作栏高度曾随各回合动作数量（单行 50px / 双行 110px）动态跳变，驱动 `layoutBoard` 导致棋盘尺寸与位置在对局过程中忽大忽小；已在窄屏/紧凑屏下恒定预留 110px 预算，`beginTurn` 移除每回合重复排版，确保对局全周期棋盘几何恒定。
- **微信开发者工具目验通过**：需求方在微信开发者工具（含 320×568 窄屏机型）中实机目验并完成多回合对局测试，确认遮挡消除、五行标签避让清晰、对局全周期棋盘尺寸稳定，整套方案通过验收。

## 勘误：归一光环从全局同步旋转改为节点独立起转时钟

此前 `_drawNodeMarks` 将全局时钟 `this._clock` 统一传给所有节点，导致所有达成归一的节点在完全相同的角度同步旋转。为真实体现节点各自达成归一的时机与状态，改为节点独立时钟。

- **独立形成时刻**：`BoardView` 内部记录各节点达成归一的时刻（`formedAt`），流光旋转与亢极外溢使用节点独立历时 `nodeTime = clock - formedAt`，流光从 12 点钟方向（`-π/2`）起转，不同时机归一的节点流光相位自然错开。
- **失去与重获**：节点因攻击受损或爆发散气失去归一时移除记录；后续重新达成归一时重置起点从 0 再次启动旋转。
- **进阶平滑延续**：节点由归一升至亢极（或亢极降回归一）时，归一未中断，保留形成时刻平滑延续；亢极外溢光效与金环共用该节点独立时钟。
- **新局重置**：对局重新开局时清空记录。
