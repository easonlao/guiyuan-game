# 法盘同心双环：内环 = 己方、外环 = 对方、外环逆时针偏移 2 格

表现层原来只有**一个** `BoardView`，由 `GameScene.projectBoard(currentPlayer, …)` 按当前行动方投影，半回合切换时这块盘**静默改换身份**，玩家无法分辨「这盘是谁的」，而「破 / 强破」要打的是**对方**盘的相克节点——对方盘根本不可见。规则层（`PlayerState.board`）其实**每个玩家各有一块盘**，共两块。

**决定**：改成一块盘、同心双环——**内环恒为己方盘（当前钉死 P1，人类）、外环恒为对方盘（当前钉死 P2，AI）**；外环相对内环**逆时针偏移 2 格（144°）**，使每根射线上「内环元素克外环元素」，且内外永远不是同一五行。

由此两个跨元素动作获得固定的几何表达：**破 / 强破 = 沿当前射线向外一格**（打对方所克元素），**化 / 强化 = 沿内环顺时针一格**（养己方所生元素）。

同时**删除内环内部的 5 条相克星弦**：己方盘内部没有任何动作走相克（相克只跨盘发生），那 5 条弦没有动作对应，是纯装饰。

## Considered Options

- **两盘并列**：375px 宽屏上每块直径 ≤180px、主印半径 ~10px、五行名字号 ~5px，不可读。
- **主盘 + 对方横条**：最省空间，但把「破」变成「按名字对应」而非「按方向」，丢掉径向手势这个几何直觉。
- **内外环同角度叠同名元素**：玩家无法区分同一方位上的两个五行属于谁，不可理解。
- **外环偏移 2 格使「外克内」**：让对方的攻击变径向，但你（P1）决策时——你需要看清的是「我这枚天干能打谁」——攻击目标反而不在你的射线上。**未采纳**，因为决策时刻最需要看清的是己方攻击方向。

## Consequences

- `BoardView.getSlot(element, polarity)` 改为 `getSlot(player, element, polarity)`，`update(BoardState)` 改为吃两块盘——表现层内部接口契约变更，归 `docs/LLD.md` §4。
- `GameScene` 里 `projectBoard` 与 `handleActionExecuted` 的「飞行期切盘」等**多处按行动方切盘的逻辑全部删除**，改为一次投影两块盘；`RuneFlightView.flyTo` 的目标坐标来源随之带 `player`。
- `tests/core/minigame-board-view.test.ts` 的坐标 / 弦数 / `getSlot` 硬编码断言会失效，需要重写。
- 「内环恒 = P1」意味着做本地双人（GDD §3 规划中的 Local PVP）时需另处理轮换，当前不为此付代价。
- 像素半径、配色、字号属工程实现，归 `docs/HLD.md` §2 Layer 3 与代码常量；本 ADR 只记编码约定（钉死内外环、偏移 2 格、破 = 径向 / 化 = 顺时针、删相克弦）。
