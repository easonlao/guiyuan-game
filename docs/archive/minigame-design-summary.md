# 归元 (Guiyuan Game) 小游戏化重构 - 架构设计概要

**版本：** V1.0 (MVP 纯单机版)  
**目标平台：** 微信小游戏  

本设计概要基于可行性研究报告 (FSR) 与软件需求规格说明书 (SRS) 编写，旨在为项目的 TypeScript 重构与 Cocos Creator 小游戏平台迁移提供架构层面的指导。

## 1. 整体架构目标

本项目采取**纯本地单机（零服务器成本）**的 MVP 策略。通过彻底剥离原有的 DOM/CSS 渲染层与 Supabase 云端数据层，将核心游戏逻辑（计算、AI、状态机）实现为环境无关的 TypeScript 纯逻辑库，并最终集成至 Cocos Creator 构建微信小游戏首包。

## 2. 核心技术栈选型

*   **编程语言**：严格遵循 TypeScript（强类型定义，彻底移除隐式 DOM/BOM 依赖）。
*   **游戏引擎**：**Cocos Creator 3.x (如 3.8 LTS)**。采用 3.x 版本以获取更原生的 TypeScript 支持和更好的长期维护，同时满足小游戏首包 < 4MB 的包体要求。
*   **数据存储**：完全脱机化，依赖本地存储。

## 3. 关键模块设计与架构策略

### 3.1 核心逻辑层与 UI 渲染层的解耦 (MVC/MVP 模式)
*   **设计原则**：严格执行渲染层解耦，原有 `src/css` 样式文件全部废弃。
*   **架构模式**：采用基于事件或接口委托的 **MVC/MVP 模式**。
    *   **视图层 (View)**：由 Cocos 引擎的 `Sprite`、`Label`、`Button` 组件接管，只负责呈现与派发用户交互事件。禁止在 UI 组件脚本中编写业务逻辑。
    *   **控制与逻辑层 (Controller/Logic)**：核心逻辑类接收交互事件，进行状态流转和得分计算，并通过事件总线 (EventBus) 或状态回调将数据变化广播给视图层进行渲染。

### 3.2 AI 性能与执行架构
*   **瓶颈风险**：复杂的 `AIController` 或 `HeadlessMatch` 可能引发主线程阻塞，导致游戏掉帧（需确保帧率 > 60FPS，单帧逻辑耗时 < 16ms）。
*   **执行策略**：在代码设计上**优先定义异步接口**（如 `Promise<Action>`）。在 MVP 阶段，底层具体实现保持同步执行以降低开发复杂度；如果后续在真机 Profiling 测试中发现性能不达标，可依靠异步接口的封装，平滑地将 AI 计算任务迁移至微信小游戏原生 `Worker`（多线程）中。

### 3.3 本地数据存储 (StorageManager)
*   **设计原则**：放弃 Supabase，满足本地对局记录、胜率和最高分等资产的持久化存储。
*   **适配器模式 (Adapter Pattern)**：为了兼容多阶段的运行环境，设计统一的 `IStorageAdapter` 接口。
    *   **阶段一 (Node.js 脱机测试)**：动态注入 `MockStorage`。
    *   **阶段二 (Cocos 预览)**：动态注入浏览器的 `LocalStorage`。
    *   **阶段三 (微信环境)**：注入基于 `wx.setStorageSync` 的微信原生存储实现。

### 3.4 核心代码目录与测试组织
*   **目录结构**：为满足快速迭代，不强制分离为 Monorepo。推荐将 TS 逻辑代码统一放置于 Cocos 项目工程的 `assets/scripts/logic/` 目录下。
*   **独立测试**：通过配置 `tsconfig.json` 和独立的测试框架（如 Jest），确保该 `logic` 目录下的核心代码既能被 Cocos 正常编译引用，也能在 Node.js 环境中进行 `Headless Match` 自动化单元测试，满足阶段一的脱机验收标准。

## 4. 实施里程碑 (Milestones)

1.  **阶段一：逻辑脱水与 TS 化**
    *   使用 TypeScript 重写所有纯计算逻辑（计分、AI权重、伤害判定）。
    *   实现存储适配器模式并提供 Mock 环境。
    *   **验收**：在 Node.js 环境下 100% 跑通 Headless 测试。
2.  **阶段二：引擎接入与 UI 重建**
    *   在 Cocos Creator 3.x 中构建工程，导入逻辑代码。
    *   搭建占位符 (Placeholder) UI 并完成 EventBus 的双向绑定。
3.  **阶段三：微信打包与上机真测**
    *   导出微信小游戏工程。
    *   重点进行 AI 运算性能监控 (Profiling)，如遇卡顿则启用 Worker。
    *   发布体验版完成真机验收。
