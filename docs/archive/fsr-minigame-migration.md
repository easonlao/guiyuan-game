# 归元 (Guiyuan Game) 小游戏化与纯单机方案可行性研究报告 (FSR)

## 1. 项目背景与目标
*   **当前现状**：项目核心逻辑使用原生 JavaScript 开发，基于 Vite 构建，前端 UI 依赖 DOM/CSS，数据/后端依赖 Supabase。代码库中包含了复杂的 `AIController`、`ScoreCalculator` 及 `HeadlessMatch` 等重逻辑模块。
*   **重构目标**：将项目整体迁移至**微信小游戏**平台，采取**纯本地单机（零服务器成本）**的 MVP（最小可行性产品）策略，优先保证核心玩法落地。

## 2. 核心架构改造方案
为适应微信小游戏环境并实现零成本，技术栈调整如下：
1.  **编程语言**：JavaScript (ESM) ➡️ **TypeScript**
2.  **渲染引擎**：原生 DOM/CSS ➡️ **Cocos Creator 2D**
3.  **数据存储**：Supabase (BaaS) ➡️ **本地缓存封装层 (StorageManager / wx.setStorageSync)**

---

## 3. 技术可行性评估 (Technical Feasibility)

### 3.1 核心逻辑复用度：**极高 (High)**
现有项目的目录结构规范（业务逻辑已抽离至 `src/js/logic/` 和 `src/js/state/`）。这些纯计算代码（如计分、AI权重、伤害判定）与宿主环境（浏览器 DOM）无关，可以 100% 低成本翻译为 TypeScript 并直接在 Cocos Creator 中运行。

### 3.2 引擎兼容性：**完美匹配 (Perfect Match)**
Cocos Creator 是微信小游戏生态的头部引擎，原生支持 TypeScript。将迁移后的纯逻辑 TS 脚本作为独立模块引入 Cocos 中，与 Cocos 的生命周期脚本进行数据绑定即可，技术上不存在断层。

### 3.3 数据存储脱机化：**完全可行 (Feasible)**
单机游戏无需实时同步，通过编写一个通用的 `StorageManager` 代理，拦截原本发往 Supabase 的读写请求，将用户资产、对战记录序列化后存入本地即可满足 MVP 需求。

## 4. 经济与时间成本评估 (Economic Feasibility)

### 4.1 资金成本：**绝对 0 元**
*   **服务器/数据库**：砍掉远端依赖，0 成本。
*   **开发工具**：Cocos Creator 免费，微信开发者工具免费。
*   **上线发布**：微信小游戏个人开发者账号注册免费，提审免费。

### 4.2 时间成本：**中等可控**
*   **TS 类型化**：预计花费 1-2 天。由于现有 JS 代码模块清晰，只需补充 Interface 和类型声明。
*   **UI 重写**：**（主要时间消耗点）** 原有的 CSS 和 DOM 结构作废，需要在 Cocos 编辑器中重新拼装 UI 节点并绑定事件。对于 MVP 阶段，可采用极简 UI（色块+文字）快速打通流程。

## 5. 潜在风险与建议对策 (Risk Analysis)

| 风险点 | 风险描述 | 应对策略 / 解决方案 |
| :--- | :--- | :--- |
| **手机端 AI 性能瓶颈** | 现有的 `AIController`、`HeadlessMatch` 若在低端手机的主线程跑高强度的遍历或权重计算，会导致游戏画面严重卡顿掉帧。 | 1. 限制 AI 的计算深度或每帧计算时间。<br>2. 接入微信小游戏原生支持的 `Worker`（多线程），将 AI 计算丢到子线程处理。 |
| **存档丢失风险** | 纯本地单机模式下，玩家若删除微信小程序或清理微信缓存，游戏进度将彻底丢失。 | MVP 阶段接受此损耗。待游戏跑通后，可随时零成本接入“微信游戏圈”的云存档 API，或后期花少量成本开通微信云开发接管存档。 |
| **防作弊能力差** | 纯前端计算，本地缓存极易被破解者修改金币或卡牌属性。 | 对于单机体验优先的 MVP 产品，**无需过度关注防作弊**。当产品被验证成功并转型联机对战时，再将 TS 逻辑抽离至后端验证即可。 |

## 6. 实施路线图 (Roadmap)

建议分以下三个阶段推进：

### 🟢 阶段一：逻辑“脱水”与 TS 化 (当前阶段)
*   隔离网络层，将 `Supabase` 相关代码替换为本地 Mock 存储。
*   将 `src/js/logic` 目录全面翻译为纯粹的 TypeScript，定义好核心接口（`Interfaces`）。
*   **验收标准**：通过本地 Node.js 运行 Headless 测试，所有逻辑和算分无报错。

### 🟡 阶段二：引擎接入与 UI 重建
*   安装 Cocos Creator，导入阶段一产出的 TypeScript 逻辑库。
*   使用占位图（Placeholder）搭建主界面、战斗界面、结算界面。
*   完成 Cocos UI 交互与底层 TS 逻辑的事件绑定。

### 🔴 阶段三：微信打包与上机真测
*   通过 Cocos 导出为“微信小游戏”工程。
*   在“微信开发者工具”中进行性能 Profiling（重点排查 AI 运算时的帧率）。
*   发布体验版，使用真机扫码验证核心循环。
